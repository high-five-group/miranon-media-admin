## Del 3 — Process-haveri avtäckt: tre fel + rot-asymmetri

### Hur det avtäcktes

Efter ADR-042-landning föreslog Chat att gå vidare utan att uppdatera todo, och därefter direkt till Fas 2.5. Marcus fångade: (1) todo måste uppdateras; (2) ingen sessionsavslutning utförd; (3) **inget sessionsdok hade någonsin skapats.** I en testande ny chatt visade sig (4) Chat kunde inte rekonstruera sessionsnummer/läge.

### De fyra felen, klassade

- **Fel 1 + 3 + 4** — reella, samma rot: levande artefakter (todo, sessionsdok) föds/uppdateras inte i takt med förändring.
- **Fel 2** — nyanserat: vi var inte vid sessionsslut (Session 10 fortsatte), så full avslutsrutin var inte förfallen. Det som saknades var löpande checkpoint + todo-kadens, inte hela ritualen.

### Rot-asymmetrin

Code styrs av plugin-skills; Chat av Project Instructions. Lifecycle-HUR bor i en skill bara Code ser; Chat *instrueras dirigera* lifecycle men rekonstruerar ur ofullständig prosa och saknar varje utlösnings-mekanism. Doc-födelse-regeln fanns redan som universell lesson (P1, 2026-05-04) men var aldrig inkodad i operativa sekvensen.

### Research: haverierna har namn

Anthropics multi-agent-research namnger två haveri-lägen för långkörande agenter: kontext-förlust-inkoherens + för-tidig wrap-up nära kontextgränsen — exakt fel 3 och 4. Mitigering: externt minne + noggranna handoffs. Sessionsdoket ÄR det externa minnet; det fanns inte.

## Del 4 — ADR-043: session-lifecycle som två-ytors skill-par + PI bas/delta

### Forensik + research-före-arkitektur

Den styrande ADR:n (ADR-034 p.9, leveransyte-modellen) lästes i sin helhet: `Customize > Skills` "används medvetet inte — disciplin ska vara alltid-på, inte upptäcktsberoende." Men Marcus skilde *auto-upptäckt* (discovery-beroende, K8-felklassen) från *explicit `/`-anrop* (deterministiskt, inget upptäcktsmoment). Förstapartskälla (Claude Help Center) bekräftade att claude.ai stödjer explicit `/`-anrop av skills. Discovery-invändningen föll; drift-invändningen visade sig vara samma manuella sync-drift PI redan accepterar (och konto-nivå-skill = mindre drift än per-spoke-PI).

Research grundade två claims: orchestrator-worker (Anthropics multi-agent-research — extern minne + handoff-kontrakt: mål/output-format/verktyg/gränser + status-fält) och config-arv bas+overlay (Kustomize/hierarkisk — grund hierarki, per-sektion-override).

### Beslut (ADR-043, Proposed)

Tre-lagers leveransmodell efter *när* innehåll måste vara aktivt: alltid-på (PI/CLAUDE.md) → lifecycle (skill) → externminne (sessionsdok). Lifecycle som två-ytors skill-par (Chat-halva orkestrerar, Code-halva utför) bundna av explicit handoff-kontrakt. Skill-set: Chat = {session-start, session-end, session-resume}; Code = befintliga 4 + create-session-doc *i* session-starts Code-halva (13-stegs som referensfil). session-resume asymmetrisk (Chat-skill; Code återanvänder session-starts LÄS-fas, ingen ny Code-skill). PI blir bas (hub, gemensam alltid-på) + tunn per-spoke-delta; lifecycle-HUR flyttar ut, alltid-på stannar.

### Den bärande begränsningen

Alltid-på meta-disciplin får INTE flytta in i en anropad skill — den måste vara aktiv varje tur, inte bara vid anrop. Endast lifecycle (ögonblicks-aktiv) flyttar. Detta band Marcus tråd om PI-flytt.

### Leverans + commit-trail (Del 4)

ADR-043 författad (Proposed). Commit-trail finaliseras vid stängning (ADR-043-fil + README 42→43 + katalog-rad; sessionsdok; todo; BUILD-LOG).

## Del 5 — Meta: sessionen demonstrerade sitt eget tema

**Sessionen byggde code-roll-disciplin och bröt sedan omedelbart lifecycle-disciplin** (skapade aldrig ett sessionsdok) — vilket avtäckte behovet av ADR-043. Rekursionen är ärligt noterad: vi byggde extern-fångst-arkitektur i den session där Chat-self-fångst (~9 %) tre gånger missade (todo-kadens, doc-födelse, ett hedge-ord om eget icke-utfört arbete), och Marcus-pushback (~27 %) fångade varje gång. Roll-arkitekturen validerade sig själv genom att fånga sina egna brott.

ADR-042 + ADR-043 delar samma skiljelinje: leveransmekanism väljs mot *när beteendet måste vara aktivt* (p.8-principen), tillämpad på meta-disciplin (alltid-på) respektive lifecycle (ögonblick).

## Del 6 — Lessons (kandidater, skördas vid stängning)

- **L66 [UNIVERSAL]** — Handoff-formulering ("egen skill") är inte ett mekanismbeslut. Beteende-klass avgör (ADR-034 p.8); ett handoff-mekanismval ska falsifieras mot kriteriet *innan* bygge, inte verkställas för att handoffen sa så. Mönsterförstärkning av L_AAA (slutsats utan empirisk grund).
- **L67 [UNIVERSAL]** — Levande artefakter (sessionsdok, todo) har landnings-kadens, inte avsluts-kadens. Doc-födelse vid sessionsstart, todo-uppdatering vid landning. Kadensen måste inkodas i operativ sekvens, inte hänga på konvention (~9 %-zonen).
- **L68 [UNIVERSAL]** — Regel-finns-men-oanvänd: doc-födelse-regeln fanns som universell lesson (P1) men var aldrig inkodad i sessionsstart-sekvensen. Att *läsa* lessons vid start ≠ att *operationalisera* dem. Mönsterförstärkning av K2.14 (sök/använd befintlig regel före uppfinning).
- **L69 [UNIVERSAL]** — Frånvaron av en handling Chat själv utförde/inte utförde i en kontext är inte disk-state som kräver verifiering. Att hedga med "tror" om eget icke-utfört arbete är fel tillämpning av verifierings-disciplinen — det gömmer ansvar bakom en regel.
