## Del 2 — Grillad samsyn: AFK-batch-kontraktet (T71/T61, 5 beslut)

> Landning 2026-07-11. Grillningen kördes med 5-punkts-agendan ur Del 1, en
> fråga i taget med Code-rekommendation per fråga; Marcus kvitterade
> rekommendationen på samtliga fem ("Går på din rekommendation!" ×2 · "A,
> bra med inbyggd omprövningströskel" · "A" · "A"). Dok-födelsens
> CI-kvittens bokförd här: run `29145123124` på `ed5d2f0` grön per jobb
> (Lint+Audit+TypeCheck ✓ · Docs link check körd+grön ✓ · Test+Build
> by-design-skippad · Detect changed files ✓).

**Beslut 1 — Review-modellen: granskningsfärdig-läget.** Loopen driver
UI-skivor till kod + mekanisk facit-avprickning (computed-style/skärmdump)
committad + CI grön per jobb + AC avbockade; **DoD #5 (design-review) lämnas
öppen**, kortet lämnas `In Progress` med not "väntar design-review";
**Done-flippen är Marcus.** Icke-UI-skivor drivs hela vägen till Done.
Beroende-kedjor körs därmed i **granskningsvågor** — en design-miss
propagerar aldrig förbi sin våg. Precedent: 4.2-praxis (S56: kod committad →
Marcus-granskning → Done). L220 + L245/L246 står oförändrade. Alternativen
HITL-omklassning (tömmer batchen på UI-tunga PRD:er) och design-review på
QA-kortet (river L220-grinden per skiva; miss kan bygga in sig i senare
skivor) avvisade — det senare omprövas när facit-assertions bevisat sig
över några batchar.

**Beslut 2 — Stop-policyn: halt-first + hård-gräns-paketet.** Batchen
stannar vid första STOPPA-/abort-utfall (kortet står i `To Do` med
avbrotts-not per do-work:s befintliga abort-väg; batch-rapporten pekar ut
det). Hårda gränser: max antal kort per avfyrning (Marcus sätter per batch;
default lågt ~3) · aldrig samma kort två gånger i samma batch (studsat kort
behöver Marcus ögon, inte nytt försök) · valfritt token-budget-tak ·
kill-switch när som helst; omstart idempotent via backlog-tillståndet.
Tids-tak avvisat (klockan är avstängd i orkestrerings-skript by design;
kort-tak + budget är de ärliga spakarna). Skip-and-continue avvisad v1
(batch-globala problem får annars upprepa sig); klassad hybrid avvisad
(stopp-klassning = agent-omdöme i svagaste läget, 9 %-empirin).
Branschgrund: stop-villkor ska vara hårda externa gränser, inte
agent-omdöme (precedent-rapportens konvergenspunkt; Ralphs frånvaro av
stop-villkor har "broken codebase" som dokumenterat failure mode).

**Beslut 3 — Gransknings-ytan: trunk-push per skiva (normen bevaras), med
inbyggd omprövningströskel.** Batchen pushar `main` per kort precis som
interaktiva do-work (DoD #3 oförändrad); revert är etablerad väg.
**Omprövningströskel (durabel):** när appen går i skarp Lotta-drift ELLER
batchar växer förbi ~5 kort tas branch/draft-PR-frågan upp som egen
landning. Mekanik-fakta bokförda för den framtida landningen: CI triggar ej
på icke-main-push utan öppen PR (`on:`-blocket verifierat), och
squash-merge hade rivit SHA-bevisen i final-summary-raderna
(merge-commit-krav om branch-formen väljs). Differentierad väg
(trunk/branch per kort-typ) avvisad som komplexitet över golvet.

**Beslut 4 — Kvittot + substratet: orkestrerings-skript i session; skill
vid bevis; ADR-071 vid bygget; allowlist-förkrav.** Loopen körs som
orkestrerings-skript (workflow) i Code-sessionen: frisk subagent-kontext
per kort (uppfyller do-work:s "nästa kort tas i frisk session"-intention),
besluten 1–3 kodade deterministiskt i skriptet, schema-tvingad
status-rapport per kort, Code kvar som orkestrerare (live-följbart,
avbrytbart). Piloten körs på Marcus explicita klartext-order
(kontrakts-erkänd opt-in-väg). Vid bevisad pilot: **`/work-batch`-skill i
hubben** (Marcus-avfyrad, `disable-model-invocation: true`;
skill-instruktion-som-anropar-workflow är harness-erkänd opt-in-form) —
batch-ordern blir samma durabla kvitto-klass som per-kort-ordern är idag
(kvitto-sömmens konsent-modell vidgas öppet, aldrig tyst). **ADR-071
mintas vid bygget** — baren nådd 3/3 (konsent-söm-lås många körningar
bygger på · överraskande utan kontext · verklig avvägning) — och bär:
batch-kvittot, substratvalet, beslut 1–3 inkl. omprövningströskeln,
headless-spåret (`claude -p "/do-work"`, doc-verifierat fungerande) som
dokumenterad framtida form för CI/cron, samt begreppet
**orkestrerings-skript** med hemvist SYSTEMET.md (ej ORDLISTA.md —
produktdomän; T71:s begreppskrock-lösning). Allowlist-förkrav före piloten:
`permissions.allow` för exakta DoD-kommandon i spoke
`.claude/settings.json` (granskningsbar diff, Marcus-kvitterad).
Headless-först avvisad (svagare observabilitet/rapport-struktur);
skill-utan-pilot avvisad (bryter minimal-test-regeln; noll workflows körda
i systemet än, T71:s ärlighets-rad).

**Beslut 5 — Piloten: TASK-3 ensam, max 1 kort.** Sekvens: AC-förslag
(Code) → Marcus-kvittens → AC + `ready-for-agent` sätts via backlog-CLI:t
på Marcus order (klassningen är Marcus, utförandet Code; fynd-karantänen
respekterad) → allowlist-diffen → Marcus-kvittens → pilot-körning. TASK-3 =
renaste minimal-testet: ingen UI-yta ⇒ ingen DoD #5 ⇒ bevisar hela kedjan
inklusive autonom Done-flip, noll S56-intrassling, och härdar
återkopplingsslingorna (delayMs-flaket, 3 kända filer) som alla framtida
batchar vilar på. Kö-prioriteringen hade ändå valt den (infrastruktur före
features). **TASK-4-resten = batch 2** efter pilot-utvärdering, körd under
S61 eller senare session med öppet övertagande bokfört i både S61-dok och
S56:s stängning i Marcus-takt (ingen tyst rivning av S56:s KVAR-lista).
Alternativen (pilot med UI-skiva, ensam eller i par) avvisade: en pilot ska
ändra EN variabel i taget, och UI-vägen kan per definition inte bevisa
Done-flippen.

**Ej-i-scope-bekräftelser** (ur Del 1, oförändrade av grillningen):

ultracode-default · agent teams · AT-Max-svepet · schemaläggning/cron.
