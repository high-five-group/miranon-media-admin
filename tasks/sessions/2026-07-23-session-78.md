## Del 1 — Syfte och scope

### Syfte

Implementera våg 2a och 2c av den riskanpassade CI-designen: gör
presubmit-svitens omfattning riskproportionell (D1-klassen), sluta köra
om identiskt innehåll vid merge (tree-dedup), lägg post-submit-nätet
som gör skippen försvarbara (nightly + larmkedja), gör hastigheten
mätbar (`scripts/ci-metrics.mjs`), och verkställ rött-först-bärarbytet
så avsiktligt röda runs lämnar den delade kön. I samma våg betalas
S77-incidentens öppna bevis-skuld: aggregatorns FAIL-gren har aldrig
bevisats fyra skarpt (L322 — den fixade fail-closed-formen är
konfig-verifierad, ej gate-bevisad).

Våg 1 är exekverad (ADR-076, PR #99). Våg 2b (visual regression från
noll) publiceras som skiva denna session men byggs i egen session; våg
3 väntar på bas-maximeringens designfönster.

### Bärande invarianter (ur design-doket, styr skivningen)

- **Sekvens-invarianten:** D1-skippet och merge-dedupen aktiveras ALDRIG
  utan nightly i samma våg. Nightly är post-submit-nätet under
  presubmit-selektionen (Google-modellen) — landar nightly efter, står
  repot en period med selektion utan nät.
- **Fail-closed:** varje klassning är en allowlist; okänt ⇒ D3. Dedupen
  får bara ge falsk-KÖRNING, aldrig falsk-skip (nyckeln är
  innehållsadresserad av trädet).
- **Paraplyet består:** jobb skippas internt med `if:`, aldrig via
  workflow-level path-filter. Aggregatorn `ci-passed` behåller
  `if: ${{ always() }}` ENSAMT och sitt explicit exit:ande steg —
  L322-regeln är icke förhandlingsbar och får inte regressa när nya
  jobb läggs till `needs`-listan.
- **Gate FÖRE handling** (L149-recidivet i S77): markdownlint och Vale
  gatar commit/push, aldrig som `&&`-kedja efter.

## Del 2 — Spec-landningen: PRD task-36 + åtta skivor (PR nr 105)

**Dok-födelse** `f89d39f` → PR nr 104 auto-mergad (`db6ef53`); run
30027125658 grön per jobb (Docs link check KÖRD + grön; Test+Build
docs-only-skippad by design). Branch städad lokalt + origin.

**`/to-prd`:** PRD-kortet **TASK-36** "Riskanpassad CI — T85 våg 2"
publicerat via backlog-CLI:t med tre spec-specifika DoD-poster utöver
projekt-defaults (statiska workflow-grindar · kontrastbevis med citerade
körnings-ID · L322-invarianten oregresserad).

**Skarv-kvittensen** (skillens enda avstämning) kvitterad av Marcus:
högsta BEFINTLIGA skarv per artefaktklass, ingen ny skarv uppfunnen —
kontrastbevis-runs för klassning/dedup (TASK-15-precedenten),
`test-<skript>`-mönstret för mätskriptet (9 skript bär redan formen),
gate-proof-workflowen som sitt eget test, befintliga statiska grindar för
workflow-filerna. Det avvisade alternativet bokfört öppet: flytta
klassningen till ett eget skript med ~15 unit-fall. Motiv mot: D0 har levt
deklarativt sedan ADR-029 och dess enda verkliga bugg var en action-INPUT-
bugg (quotepath, TASK-15) som ett logik-test inte hade fångat — det var
kontrastbevis-runs som fångade den; ett eget skript hade dessutom tvingat
fram omimplementation av glob-semantik som actionen redan äger, med
divergens-risk mot D0:s exkluderingar.

**RIVNING — cache-dedupen falsifierad (öppen, ej tyst).** Marcus frågade
vid skarv-kvittensen om underlaget räckte "både internt och externt".
Svaret var nej: 2a vilade på en obeverifierad teknisk antagelse. Riktad
web-research mot förstapartskällan (GitHub Docs, *Restrictions for
accessing a cache*, två oberoende hämtningar) gav verbatim: *"When a cache
is created by a workflow run triggered on a pull request, the cache is
created for the merge ref … can only be restored by re-runs of the pull
request"* + *"Workflow runs cannot restore caches created for child
branches or sibling branches."* Design-dokets mekanism (gröna PR-runs
skriver `green-tree-<hash>`, main-push-runs läser) hade alltså gett
PERMANENT cache-miss — noll besparing plus en onödig skrivning per PR,
utan att någonsin se trasig ut (grön CI, inga fel, tyst utebliven vinst).

Marcus valde **väg A**. Ersättaren bevisad mot faktisk disk + API FÖRE
den föreslogs, på merge-commit `db6ef53` som sessionen själv skapat:
merge-tree `1eaa2bb96de9e29916d0bb32c094af89c030a43c` ≡ PR-head-tree
(samma hash), och `gh run list --commit f89d39f2c6…` returnerade
`conclusion: success`. Main-runnen läser alltså `HEAD^2`, verifierar
tree-ekvivalensen och frågar körnings-API:t — ingen ny lagringsyta,
fail-closed på varje avvikelse, och steget bor i `changed`-jobbet som
redan har `fetch-depth: 0` ⇒ **ADR-039/054-invarianten orörd**.
Rättelse-not landad i design-doket (ursprungsformen bevarad genomstruken
för spårbarhet); ADR-077 bär rivningen i sin kontext.

**`/to-issues`:** åtta kort under TASK-36 i beroendeordning — 36.1
gate-proof (oberoende, betalar S77:s bevis-skuld, EGEN fil ⇒ enda
kollisionsfria skivan) · 36.2 nattnätet · 36.3 D1-klassen + hygien-posten
· 36.4 merge-dedupen · 36.5 mätskriptet · 36.6 rött-först-bärarbytet (2c)
· 36.7 visual (2b, `ready-for-human` — baselines är bilder någon måste

**Sekvens-invarianten är kodad som beroenden, inte buren av minne:**

## Del 3 — Batch-exekvering: 36.1 gate-proof (work-batch, kort 1/3)

Marcus invokerade `/work-batch` (max-kort 3, korten 36.1/36.2/36.5
seriellt; grind-skivorna 36.3/36.4/36.6 medvetet utanför). Avfyrnings-
tillstånd rapporterat i trailen före start (förkrav gröna: Backlog-instans
· AFK-allowlist bär DoD-kommandona · deps uppfyllda av seriell ordning).

**Kort 1/3 — task-36.1 (gate-proof-workflowen) DONE.**

**Subagent-kontext-friktionen (process-fynd, lesson-kandidat).** Första
do-work-subagenten byggde `.github/workflows/gate-proof.yml` (ny fil,
kollisionsfri), öppnade leverans-PR #107 med ren scope, bockade
DoD-grindarna och armerade auto-merge — men dess kontext kunde inte
överleva CI-väntan (staging-jobbet ~8 min), så den returnerade FÖRE
gate-proof-avfyrningen + stängnings-PR:n. Kortet stod korrekt In Progress
(inget halt, ingen felaktig stängning). Orkestratorn (huvudsessionen)
disk-verifierade det FAKTISKA läget (litade aldrig på agentens ord) och
slutförde svansen. **Form-justering för resten av batchen:** do-work:s
asynkrona tvåstegs-svans (leverans → CI-vakt → stängning) ryms inte i en
engångs-subagents kontext — orkestratorn äger CI-vänta + merge + stängning
(parallell-formens ADR-073-steg-4-rollfördelning tillämpad seriellt).

**Designgranskning (orkestratorn avfyrar aldrig blint).** gate-proof.yml är
korrekt och tvåsidig: `forced-red` (step-COE ⇒ jobbet grönt, outcomen
failure), `umbrella-replica` (kör den VERBATIM fail-closed jq-grenen ur
`ci-passed`), `assert-proof` (enda jobbet utan continue-on-error ⇒ färgar
körningen). Ärlig om plattforms-tvingade avvikelser (GitHub kan ej visa
rött jobb i grön körning; job-nivå-COE hade maskerat needs.result +
REST-conclusion, actions/toolkit#1739 — därför step-COE + jobb-output).
