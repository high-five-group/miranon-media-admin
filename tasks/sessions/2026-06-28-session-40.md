### STEG 0 — strukturobservation (throwaway-probe, ej committad)

- M2 värde-fritt bekräftad i föregående pass (RESEND_API_KEY + RESEND_FROM staging).
- Engångs throwaway-EF (`l2d-resend-probe`, `--no-verify-jwt`, raderad direkt + aldrig
  committad) gjorde en riktig `batch.send` mot `delivered@`/`bounced@resend.dev` och
  returnerade ENBART struktur. Observerat mot resolverad `resend@4`: `data` keys=`["data"]`,
  `data.data` = array(2) av `{id:string}`, **`errors` FRÅNVARANDE (undefined)** vid 2/2 giltiga,
  ingen top-level-error. Bekräftar `{data:{data:[{id}]}}` → ingen STOPPA. (L210.)

### STEG 1–2 — riktig svar-parsning + enhetstester (`b4677e8`)

- Ny Node-importerbar `_shared/resend-batch.ts` `parseBatchOutcome`: rejected ur
  `errors[].index → batch[index].email + message`; accepted = index-KOMPLEMENTET (rad-exakt,
  ej beroende av det kompakterade id-only `data.data`); defensiv `data.data.length`-cross-check;
  fabricerar aldrig e-post vid index utanför intervall. Ersatte L2c-platshållaren (anta-full-accept)
  i `makeRealBatchSender`. 8 api-pure enhetstester (full-accept/partial/defensiva kanter); partial-
  grenen schema-bekräftad mot Resend-doc (`CreateBatchSuccessResponse`), EJ live-framkallbar (icke-
  prod-spärren blockerar utlösande input). L2c-PIN UPPLÖST. (L208.)

### STEG 3–5 — live-verifiering mot deployad staging-EF (efemär fixtur)

- **Fixtur (L209):** seedade i ett TOMT `kurs×modalitet`-par (staging hade bara 3 RIM/Utbildning-
  rader) — HAPPY-segment (`Psionautics/Utbildning` → 2 Personer delivered@/bounced@resend.dev) +
  GATE-segment (`Fjärrskådning/Utbildning` → 1 Person `blocked@example.com`). Allt raderat efter
  verifieringen (basen är leverabel); staging tillbaka till 3 RIM-rader + tom Utskickslogg.
- **STEG 3 happy-path:** deploy `send-email` (explicit `--project-ref` staging, prod orört) →
  HTTP **200** `status:'sent'`, `requested=2` (= exakt seed-mängden → isolering bekräftad),
  `accepted=2 rejected=0`. Riktig Utskickslogg-merge: **0→1 rad** (`rec…`), 5 skrivbara fält +
  `Idempotensnyckel=jobId`, `Skickat till`=2 person-ID.
- **STEG 4 idempotens-rerun** (samma jobId): HTTP 200, **samma `logRecordId`**, radantal
  **OFÖRÄNDRAT (1)** → app-merge-idempotens bevisad. Resend 24h-idempotens via deterministisk
  `<jobId>/b<index>`-nyckel (identisk över rerun).
- **STEG 5:** (a) **503 OMVÄNT** — happy-path 200 (ej 503) med nyckel satt → ResendNotConfigured-
  grenen död i happy-path. (b) **422 gate-liveness** — GATE-segment → HTTP **422**
  `non_prod_address_refused` `offending:[blocked@example.com]`, **noll send, ingen Utskickslogg-rad**
  (radantal oförändrat).
- **Observation (ej L2d-defekt):** formel-fältet `Antal skickade` (COUNTA, ❌ aldrig skrivet)
  visade 1 trots 2 länkade `Skickat till`-records — pre-existerande bas-formel-quirk (COUNTA på
  länkfält), utanför skrivkontraktet → defekt-registret/bas-maximering (ADR-063), ej L2d.
