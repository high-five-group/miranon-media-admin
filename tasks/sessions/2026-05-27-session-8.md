## Del 1 — Syfte och scope

Session 8 är en process-retrospektiv i två steg. **K0a** (kartläggning, körd i en
tidigare Code-session, rapporterad till Chat men utan eget sessionsdok) diagnosticerade
en återkommande klass av tyst dokument-drift. **K0b** (denna session) åtgärdar de två
aktiva driftarna, bygger mekanisk enforcement mot drift-klassen, och formaliserar
principerna i en ADR. Detta dok registrerar **båda** stegen retroaktivt — K0a-diagnosen
fick inte förbli ett efemärt chat-artefakt (kontinuitet-arkitektur: filartefakter är enda
sanningskällan).

**I scope (K0b):** fixa 2 aktiva driftar; bygg 2 deterministiska CI-grindar + test-suiter;
ADR-039; sessionsdok + lessons + todo; undersök sessions-numreringskonventionen (DEL 5).

**Inte i scope (→ framåt-backlog):** plugin-operations-disciplin (Klass A, irreducibel
CC-tooling); generell konsistens-audit-skill (K0a visade ej systemiskt → undvik
överengineering); fel-hanterings-arkitektur-konsolidering (ADR-038:s öppna frågor);
Fas 2.5-arbete.

Klass B (ogrindad artefakt-drift — den proceduriella luckan): 4 · Klass C (Chat/dok-premiss
fel, fångad av Code self-review): 2. Den dominerande åtgärdsbara klassen var **B**.

**De 2 aktiva driftarna (Klass B), funna genom konsistens-svep:**

1. **README ADR-räkning sa `28`, faktiskt `38`** ADR-filer. README:s ADR-räkning uppdateras
   bara av `phase-end-verify` (fas-avslut); inget fas-avslut sedan Fas 2 (2026-05-13) medan
   tio ADR:er (029–038) tillkom i mellanfas-sessioner.

**Roten — kadens-missmatch:** den enda mekaniska doc-drift-vakten körs vid fas-avslut medan
artefakterna ändras varje session.

**Konkret bevis att kadens-missmatchen dolde en trasig check (avtäckt K0b DEL 1):**
`phase-end-verify.sh:52` greppar README efter `[0-9]+ arkitekturbeslut`. README bar token-värdet
på en **andra** rad (doc-referenslistan, "ADR-katalog (28 arkitekturbeslut)") — så `head -1`

det. (Detta korrigerar K0a:s ursprungliga utsaga att grepen "matchade ingenting" — den matchade
stale värde, inte tomt.)

**3 brister i noterat→åtgärdat:** (i) lessons är prosa utan bro till enforcement; (ii) [L50](../lessons.md):s
egen föreskrivna test byggdes aldrig (bara invariant-noten); (iii) den enda doc-drift-vakten har
fel kadens. Omfång: 2 aktiva driftar, **ej systemiskt** (badges, scripts, plugin-state, fas-status

## Del 5 — Sessions-numreringskonventionen (verifierat → förslag → STOPPA)

**Vad jag sökte:** en faktisk definition av hur sessioner NUMRERAS (heltal vs decimal; vem
tilldelar; var registreras).

**Vad jag fann:**

- [ADR-023](../../docs/decisions/ADR-023-sessions-arkivering.md) § "Konvention för framtida sessions"
  täcker sessionsdok-**filnamn** (`<datum>-<tema>.md`) + arkivering + split-tröskel — **inte**
  nummer-tilldelning.
- [byggplan.md:16](../../docs/byggplan.md) definierar **ADR**-numrering ("tilldelas av Code mot
  befintlig katalog vid commit-tillfället") — inte session-numrering.
- Ingen definition i spoke- eller hub-CLAUDE.md, byggplan, eller skills.
- **Empiriskt mönster** (otydligt formaliserat): 6 → 6.5 → 6.6 → 6.6.5 → 6.6.6 → 6.6.7 → 6.7 → 7 → 8.
  Decimaler används för inskjutna sub-/mini-sessioner mellan heltal; finare decimal = djupare insticks-nivå.

**Slutsats:** ingen formell definition existerar — samma klass som ADR-023-vs-skill-tvetydigheten
K0a loggade (styrande konvention oklart definierad).

**Förslag (ej committat — kräver Marcus):**
- **Plats:** kort sektion i spoke-CLAUDE.md `## Operativ procedur`, ELLER ny ADR-040 (nästa lediga).
- **Innehåll (utkast):** heltal = primär arbets-/fas-session; decimal = inskjuten process-/
  underhålls-session mellan heltal (varje decimalnivå = finare insticks); numret deklareras av
  Marcus + Chat vid sessionsstart och registreras i sessionsdok-titel + todo "Aktuellt fokus".

🛑 **STOPPA:** att fastställa en styrande konvention är ett beslut som kräver Marcus. Verifierat,
föreslaget — committas inte förrän Marcus valt plats + innehåll. (Separat från K0b:s atomiska commit.)
