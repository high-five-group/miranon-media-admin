### Empiriska verifieringar före designen (fakta, ej antaganden)

1. **Worktree-minimal-testet** (Workflow, 2 parallella agenter,
   read-only): distinkta worktrees under `.claude/worktrees/`, EGEN
   branch per agent (`worktree-wf_<id>-<n>`), båda på färsk main-HEAD
   (`5513c3d`), rent träd, `.git` som fil, backlog-CLI körbart från
   worktreen; auto-städning bekräftad efteråt. Luckor: `node_modules`
   saknas (npm ci krävs per worktree, ~500 MB, disk 404 GB ledigt) och
   gitignorade `.env.local`/`.env.test` följer inte med (kopieras
   lokalt vid setup — hemligheter når aldrig trailen).
2. **CI-mekaniken:** concurrency-gruppen är per PR-nummer
   (`github.event.number || github.sha`) → parallella PR:er krockar
   inte; `pull_request → main` triggar även drafts; **Test+Build kör
   `api-staging` + e2e-staging mot staging-miljön** → två samtidiga
   runs = TASK-6-kollisionen på CI-nivå (se förfining nedan). Main
   saknar branch protection → merge kräver inte up-to-date-branch.
3. **Playwright-portrisken:** `reuseExistingServer: !CI` → kvarglömd
   server på 5173 ger en annan worktrees tester FEL KOD
   (TASK-5-klassen) → ledig-port-pre-flight i semaforen.

### Designen (kvitterad form A)

- **Topologi:** ETT orkestrerings-uppdrag i Code-sessionen; max 2
  pipelines; frisk do-work-agent per kort i EGEN worktree
  (Workflow-substratet, samma väg som minimal-testet); central
  kort-UTPEKNING före spawn (aldrig auto-plock i pipelines).
- **Fasat schema (kollisionsytor hanteras deterministiskt av faser,
  inte konflikthantering i stunden):** fas 1 = **8.1 EXKLUSIVT**
  (timing-mätningens validitet: ingen samtidig last) → fas 2 =
  **8.3 ∥ 9.1** (disjunkta: persist/lockfil ↔ primitiv/demo/spec) →
  fas 3 = **8.2 ∥ 9.3** efter 9.1-merge (spec-/demo-kollisionen
  8.2↔9.1 upplöst — 8.2 appendar på mergad main; 8.2↔9.3 disjunkta).
  Ordinal-avvikelsen (A kör 8.1→8.3→8.2) öppet bokförd: ordinal är
  plock-prioritering; inom Marcus-partitionerad batch schemalägger
  orkestratorn för kollisionsfrihet; inga hårda beroenden bryts.
- **Pipeline-agentens form (pilot-delta mot do-work, öppet
  deklarerat):** kortet utpekat (inte plockat) · leverans-commit på
  kort-branch (`git switch -c task/<id>`) + push (INTE main) · steg 5b
  (stängningen) FLYTTAT till orkestratorn. I övrigt do-work oförändrad
  (steg 2–4, AC/DoD-bockar i leverans-commiten, schema-tvingad
  statusretur: ID, utfall, commits, defekter, fynd, TDD-bevis).
  Deltat kodifieras i pilot-ADR:n + skill 1.14.0 EFTER bevis.
- **Orkestratorns ansvar (seriellt per kort — förfining post-STOPPA,
  öppet bokförd):** `gh pr create --draft` → CI-vakt per jobb
  (headSha-match, L265) → vid rött: remedierings-agent i kortets
  worktree (max 1 varv, annars halt) → `gh pr merge --merge`
  (merge-commit, aldrig squash — SHA-bevisen) → main-CI-vakt →
  OBEROENDE disk-verifiering (kort-tillstånd via CLI, path-scope,
  AC/DoD) → stängnings-bokföring på main → worktree-städning.
  **Motiv för serialiseringen:** CI:s staging-steg (verifiering 2) gör
  samtidiga PR-runs till samma contention-klass som TASK-6 — hela
  PR→CI→merge→main-CI-kedjan är därför EN orkestrator-ägd kritisk
  sektion per kort; agenternas implementationsfaser (väggklockans
  dominant, 24–109 min/kort S61) förblir parallella. Flytten av
  PR-skapandet från agent till orkestrator ingår i förfiningen (inom
  kvitterad ram: samma semafor-princip på en yta som upptäcktes efter
  STOPPA:n).
- **Semafor + portskydd:** mkdir-baserat fillås i scratchpad (utanför
  repot) som agenterna tar runt ALLT som startar server eller rör
  staging (`test:api`, Playwright-sviter, 8.1:s mätning); pre-flight i
  låset: 5173 ledig. Löser TASK-5- och TASK-6-klasserna med EN
  mekanism utan att röra `playwright.config.ts`.
- **Drain-halt (samsynens beslut 5, kodat):** pipeline-fel → kortet
  To Do med avbrotts-not (do-work:s abort-väg); den friska pipelinen
  kör klart PÅGÅENDE kort, inget nytt startas; rapporten pekar ut
  halten. Hårda gränser: max-kort 5 (Marcus-satt i ordern) · aldrig
  samma kort ×2 · kill-switch · omstart idempotent via
  backlog-tillståndet.
- **Mål-tillstånd:** 8.2/8.3/9.1/9.3 → granskningsfärdiga (In
  Progress + öppen design-review-grind; Done-flipp = Marcus; 8.3 hör
  hit — persist ÄNDRAR upplevt laddläge, L269-klassen). **8.1 → Done
  direkt** (kvitterat A): read-only-mätskiva utan produktkodsdiff —
  design-review-raden "per skiva med UI-yta" EJ TILLÄMPLIG, bokförs
  öppet i final summary.
- **B-switchen:** ej i skarp Lotta-drift → v1-formen (merge vid grönt,
  granskning mot main). Switch-posten byggs i bevis-landningen.
- **Allowlist-diffen** (denna landning, egen commit): `gh pr
  create/merge/view/list` · `git worktree/switch/branch` · `npm ci` ·
  `npm install` LÅST till ADR-072:s två TanStack-paket
  (`react-query-persist-client`, `query-sync-storage-persister`) ·
  `npm run test:a11y` · `cp` låst till `.env.local`/`.env.test` från
  huvudrepots path · `lsof` · `mkdir`/`rmdir` (fillåset).
- **Rapport:** batch-rapport per /work-batch steg 4 + pilot-metrik
  (parallell väggklocka vs summerad korttid, semafor-väntetider,
  merge-konflikter [förväntat 0], worktree-setup-tid, first-pass-CI).
