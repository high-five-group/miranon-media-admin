## Del 2 — ADR-068 (WIP-utkast): Aktör-modell — arbetstyp-routad två-/tre-aktörs

### Kontext

Marcus genomgick Matt Pococks AI-kodnings-metod ("AI Coding for Real Engineers") och vill
integrera den utan att bryta vårt fungerande Chat/Code/Marcus-system. Grillning (Session 47)
fastställde att metoderna konvergerar på ~70 % (statslöshet→filer, ren kontext, progressiv
informationsdelning, ADR:er, återkopplingsslingor, skills, människan äger smak) — oberoende
framtagna. Den strukturella skillnaden är en enda: Pocock har EN agent (designar + utför + kör
slingorna själv) + människa; vi har splittrat den agenten över två ytor — Chat designar (webb,
kan ej köra slingor — strukturellt blind för maskinsignaler) och Code utför + verifierar (VS Code,
ser disk) — vilket kräver Marcus som relä.

Mätta fångst-rater (Session 8: Chat-self ~9 %, Code ~64 %, Marcus ~27 %) omtolkas i det ljuset:
Chats 9 % är inte sämre omdöme utan blindhet för maskinsignaler (self-review = läsa om egen prompt
utan att köra något); Code:s 64 % är samma mekanism som en verktygsförsedd agent (avstämning mot
exekverbara signaler). Den tredje aktören är priset för Chat/Code-splitten. Pococks uppströms-
discipliner (grillning, djupa moduler, tracer bullets) reducerar just den tvetydighet Chat felade på.

Faktagrundning (Anthropic förstaparts-källor + branschpraxis, Session 47 — för att reversera
ADR-041 på belägg, ej enbart logik): Chat (claude.ai) och Code (Claude Code) kör samma modellfamilj
— samma modell, ej olika tränad; skillnaden är selen (verktyg, system-prompt, kontext, gränssnitt),
inte hjärnan. Därför är Chats blindhet en följd av att design-rollen ligger på en verktygslös yta,
inte en modell-egenskap: en design-roll inuti Code (t.ex. en Plan/Architect-subagent) är
verktygsförsedd och o-blind. Claude Code har roll-separationen inbyggd — subagenter kör i eget
kontextfönster med egen system-prompt, egen verktygsåtkomst och oberoende behörigheter (inbyggda
Explore/Plan/general-purpose; dokumenterat Plan-Architect + Implementer-mönster). Anthropics eget
fler-agent-system använder orchestrator-worker (lead planerar + delegerar, isolerade parallella
workers, separat verifierings-pass) — men det mönstret är byggt för bredd-först parallell research
och är uttryckligen svagt för tätt kopplad kodning (~15× tokens; 90,2 %-vinsten gällde en
research-eval, ej kodning). Slutsats: tre-aktörs-reläet löste en sel-artefakt (en blind design-yta),
inte en modell-nödvändighet — den empiriska grunden för att reversera ADR-041:s default. Källor:
Anthropic Claude Code subagent-docs; Anthropic "How we built our multi-agent research system";
VS Code subagent-docs (Plan-Architect/Implementer); branschsammanställningar (kontext-isolering av
avgränsade sido-uppgifter inom en kontinuerlig kedja, ej relä för tätt kopplad kodning).

### Beslut

1. **Arbetstyp-routad aktör-modell.** Aktör-uppsättningen väljs per arbetsenhet av ett avgörbart
   artefakt-test, ej godtycke. **Routing-nyckeln — exekverbar-spec-testet:** en arbetsenhet är
   *Mode-B-redo* omm en grillad spec finns med (i) tydligt mål + acceptanskriterier, (ii) blockerare
   identifierade och lösta, (iii) etablerade testskarvar + automatiska kontroller närvarande,
   (iv) inga väntande produkt-/design-/arkitektur-/scope-beslut, (v) inga åtgärder som kräver
   behörighet utanför bandet. Identiskt med Pococks AFK-checklista och §3.1-STOPPA körda i förväg
   — en grind, tre namn.

2. **Mode B (bygg/exekvering) — default, två-aktörs.** Spec Mode-B-redo → Code är agenten:
   designar sin implementation, kör test/CI/conformance/e2e, självkorrigerar mot maskinen (får
   använda Explore/Plan-subagenter för kontext-hygien internt). Marcus kvitterar scope + granskar.
   Flöde: Marcus→Code direkt (ingen Chat-prompt att relä). Säkert här för att slingorna
   (CI/conformance/e2e) är starka precis på exekvering.

3. **Mode A (design/strategi/meta) — tre-aktörs, delad på kodbas-grundning:**
   - **3a. Människo-strategisk/process-design** (aktör-modell, stora vägval, governing-/ADR-
     författande, fler-slice-planering, grilla fram samsyn med Marcus) → **claude.ai Chat.**
     Dialogytan är värdet; kodbas-åtkomst är ej flaskhalsen — samsyn med Marcus är det. Chat
     grillar/designar med Marcus → Marcus beslutar + relär spec till Code.
   - **3b. Kodbas-grundad teknisk design** (modul-arkitektur, djupa moduler, plan-mot-existerande-
     mönster, domänmodellering mot faktisk kod) → **Code Plan/Architect-subagent** (verktygsförsedd,
     o-blind, live disk); Marcus granskar. Faktagrundning: kodbas-grundad design görs bättre av en
     verktygsförsedd agent än av en index-/relä-beroende blind Chat.
   Output från båda: en grillad spec/ADR/plan som matar Mode B.

4. **AFK-kvittens-kadens lever inuti Mode B.** Enda återstående valet i Mode B är kvittens-kadens:
   per-commit (tight, default) vs per-spec-upfront (AFK, när Marcus kvitterar AFK-behörighet). En
   AFK-slice landar alltid med explicit "vad-att-granska"-punkt. (Grillad Session 47.)

5. **Routing-ägande + skyddsnät.** Testet gäller observerbart artefakt-tillstånd; Chat föreslår
   läge, Marcus bekräftar, Code själv-routar aldrig. Code:s §3.1-STOPPA är automatisk
   Mode-B→Mode-A-degradering: träffar exekvering tvetydighet/saknat beslut/onåbart mål var specen
   ej var Mode-B-redo → STOPPA sparkar tillbaka till grillning → återinträde med skärpt spec.
   Felroutning kan ej fortgå tyst.

6. **Default + fallback.** Oklar redo-status → behandla som ej redo → Mode A (säker default;
   blockerar Mode-B-av-bekvämlighet). Tre-aktörs rivs aldrig — det är Mode A (3a) och fallback för
   Mode B.

7. **Arbets-spec-substrat: riktning git-native issues.** Mode-B-redo specar bor som issues-i-git
   (acceptanskriterier = Mode B-input; board = vilka issues är Mode-B-redo). Verktygsval
   (Backlog.md / git-issues / git-bug) defereras till egen utvärderings-/minimal-test-landning.
   Governade filer-i-git behålls som substrat.

8. **Reversibelt + mätt.** Mode B spåras mot tre-aktörs-baslinjen (CI-grön-första-passet /
   defekt-rate). Håller det — behåll. Gör det inte — re-tighta exekvering mot tre-aktörs.

### Alternativ

- **A. Behåll ren tre-aktörs (status quo, ADR-041).** Förkastat: betalar tredje-aktörs-priset även
  för exekvering, där Chat enbart är blind-designer-overhead och Code redan opererar i 64 %-regimen.
- **B. Ren två-aktörs som Pocock (kollapsa till Code för allt).** Förkastat: tappar Chats människo-
  strategiska dialogyta för svårt design-/process-arbete där samsyn med Marcus är flaskhalsen.
- **C. Arbetstyp-routad [valt].** Yt-anpassad routing: varje yta används där den empiriskt är bäst
  (bygg→två-aktörs; människo-strategisk design→Chat; kodbas-grundad design→Code-subagent), med
  självkorrigerande gräns via §3.1.
- **Öppna, ej beslutade** (grillas vidare Session 47): issues-verktygsval (egen landning),
  grillnings-disciplinens mekanism, CONTEXT.md-placering, ADR-harmonisering mot Pococks
  3-villkors-test, PRD↔byggplan, prototype, diagnosing-bugs.

### Konsekvenser

- *Ändras:* routing per arbetsenhet; sessioner taggas Mode A/B (kan skifta mitt i — en design-session
  föder en spec och lämnar till bygge); handoff-kontraktet styr Mode A:s Chat→Code-edits; Mode B kör
  Marcus→Code direkt.
- *Mode A-delningen flyttar kodbas-grundat design-arbete till Code:* planen i
  `plan-djupa-moduler-och-arkitekturgranskning.md` (improve-codebase-architecture / djupa moduler) är
  Mode 3b och hör hemma i Code:s Plan/Architect-subagent mot live disk, ej i Chat mot index.
- *Bevaras:* tre-aktörs (Mode 3a + fallback); all governance (lifecycle-skills, CI-grindar,
  frontmatter-policy, count-tokens) i alla lägen; alla filer förblir governade git-artefakter.
- *Namngiven risk:* i Mode B är Marcus enda mänskliga kontroll på Code (ingen Chat-design-checkpoint,
  ingen relä-fångst). Mildras av: starka slingor exakt där Mode B gäller; bygg/design-gränsen som
  också är en risk-gräns (svaga-slinge-arbete stannar i Mode A); §3.1-degraderingen.
- *Supersession:* reverserar ADR-041:s default (tre-aktörs alltid). ADR-041:s empiriska grund
  bevaras — tre-aktörs förblir för design/process (3a) + fallback; endast exekverings-defaulten
  flippar. Låset kräver att återstående forkar grillats och residual research-koll gjorts.
