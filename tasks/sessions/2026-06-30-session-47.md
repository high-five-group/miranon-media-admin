### Kontext

Marcus genomgick Matt Pococks AI-kodnings-metod ("AI Coding for Real Engineers") och vill integrera
den utan att bryta vårt fungerande system. Grillning (Session 47) fastställde att metoderna konvergerar
på ~70 % (statslöshet→filer, ren kontext, progressiv informationsdelning, ADR:er, återkopplingsslingor,
skills, människan äger smak) — oberoende framtagna. Den strukturella skillnaden är en enda: Pocock har
EN agent (designar + utför + kör slingorna själv) + människa; vi splittrade den agenten över två ytor —
Chat designar (webb, kan ej köra slingor — strukturellt blind för maskinsignaler) och Code utför +
verifierar (ser disk) — vilket kräver Marcus som relä.

Mätta fångst-rater (Session 8: Chat-self ~9 %, Code ~64 %, Marcus ~27 %) omtolkas: Chats 9 % är inte
sämre omdöme utan blindhet för maskinsignaler (self-review = läsa om egen prompt utan att köra något);
Code:s 64 % är samma mekanism som en verktygsförsedd agent. Den tredje aktören var priset för splitten.

Faktagrundning (Anthropic förstaparts + branschpraxis, Session 47): Chat (claude.ai) och Code (Claude
Code) kör samma modellfamilj — samma modell, ej olika tränad; skillnaden är selen (verktyg, system-prompt,
kontext, gränssnitt), inte hjärnan. Chats blindhet är därför en sel-artefakt, inte en modell-egenskap.
Claude Code har roll-separation inbyggd (subagenter med eget kontextfönster, egen system-prompt, egen
verktygsåtkomst; Explore/Plan/general-purpose; dokumenterat Plan-Architect+Implementer-mönster), så en
design-roll inuti Code är verktygsförsedd och o-blind. Anthropics eget fler-agent-system (orchestrator-
worker) är byggt för bredd-research och uttryckligen svagt för tätt kopplad kodning (~15× tokens; 90,2 %-
vinsten gällde research-eval). Vidare: Pococks grillnings-regel säger att en fråga som kan besvaras genom
kodutforskning ska utforskas, inte frågas — en separat Chat-yta kan strukturellt inte köra kodbasen mitt
i en grillning (söker index / relär), medan Code läser live disk; grillning är alltså BÄTTRE grundad i Code.
Kontext-separationen en separat yta gav uppnås med en separat Code-session (ren kontext mellan strategi och
bygge). Slutsats: ingen bärande funktion kräver en separat Chat-yta; tre-aktörs-reläet löste en sel-artefakt,
inte en modell-nödvändighet. Källor: Anthropic Claude Code subagent-docs; Anthropic "How we built our
multi-agent research system"; VS Code subagent-docs (Plan-Architect/Implementer); branschsammanställningar.

### Beslut

1. **Två-aktörs (Code + Marcus) blir enda aktör-modell.** Code är agenten (designar + utför + kör
   slingorna; får använda Explore/Plan-subagenter för kontext-hygien och kodbas-grundad design internt);
   Marcus äger scope, smak, prioritering, review. Ingen tredje aktör som stående läge.

2. **claude.ai (Chat) pensioneras som påbjuden yta.** Ej längre del av den operativa modellen. Får
   användas av Marcus som valfritt isolerat bollplank, men ingen arbets-output eller governance hänger
   på den.

3. **Grillningen flyttar in i Code.** Pococks grillnings-disciplin körs i Code-sessionen (Matts väg),
   bättre grundad (utforskar live disk hellre än att fråga/relä). Kodbas-grundad design (modul-arkitektur,
   djupa moduler, plan-mot-mönster, domänmodellering mot faktisk kod) körs i Code mot live disk — inklusive
   planen i plan-djupa-moduler-och-arkitekturgranskning.md.

4. **Kvittens-kadens (AFK, away-from-keyboard) består, inom två-aktörs.** Enda loop-valet är kvittens-kadens: per-commit
   (tight, default) vs per-spec-upfront (AFK, när Marcus kvitterar AFK-behörighet). En AFK-slice landar
   alltid med explicit "vad-att-granska"-punkt. (Grillad Session 47.)

5. **Exekverbar-spec-testet (AFK-behörighetsgrind).** En arbetsenhet är AFK-redo omm grillad spec med
   (i) tydligt mål + acceptanskriterier, (ii) blockerare lösta, (iii) etablerade testskarvar + automatiska
   kontroller, (iv) inga väntande produkt-/design-/arkitektur-/scope-beslut, (v) inga åtgärder som kräver
   behörighet utanför bandet. Identiskt med Pococks AFK-checklista och §3.1-STOPPA körda i förväg.

6. **Disciplinerna migreras, ytan pensioneras — separat landning.** Chat-sidans ren-relä-apparat
   (4-zoners-output, Chat→Code handoff-kontrakt, Chat-halvorna av session-skillsen) fanns enbart för att
   Marcus var relä mellan två ytor och RETIRERAS. Värdebärande discipliner MIGRERAS in i Code:s operativa
   modell innan apparaten pensioneras: prompt-design-rigor (forensisk pre-pass, klassning, research-före-
   arkitektur), meta-disciplinerna (11/10, verifiera-aldrig-gissa, triage-av-det-oväntade, evenhandedness),
   lessons-skörd, lifecycle-logik. Pococks grillnings-disciplin är ersättaren för design-rollen Chat lämnar.
   Migrerings-/retirerings-/arkiverings-kartan designas och körs som egen landning.

7. **Arbets-spec-substrat: riktning git-native issues.** AFK-redo specar bor som issues-i-git;
   verktygsval (Backlog.md / git-issues / git-bug) defereras till egen utvärderings-/minimal-test-landning.
   Governade filer-i-git behålls som substrat.

8. **Reversibelt + mätt + arkivera-inte-radera.** Två-aktörs adopteras som enda läge nu, MEN Chat-sidans
   apparat ARKIVERAS (ej raderas) och denna ADR förblir Proposed/reversibel tills två-aktörs är bevisat hos
   oss (CI-grön-första-passet / defekt-rate mot tre-aktörs-baslinjen från 46 sessioner). Håller det — radera
   apparaten på riktigt + gradera ADR till Accepted. Gör det inte — re-aktivera tre-aktörs-fallback från arkiv.

### Alternativ

- **A. Behåll tre-aktörs (status quo, ADR-041).** Förkastat: tredje aktören löste en sel-artefakt (blind
  design-yta), ej en modell-nödvändighet; betalar relä-skatt utan bärande motvärde.
- **B. Behåll Chat som påbjuden strategi-yta (tidigare S47-förslag, Mode 3a).** Förkastat under grillning:
  ingen funktion kräver den — design-intelligens är samma modell i Code; grillning är bättre grundad i Code;
  kontext-separation fås via separat Code-session.
- **C. Två-aktörs som enda läge, Chat pensionerad [valt].** Rent Pocock-spår; behåller bara struktur som
  bär sin vikt; reversibelt + mätt.
- **Öppna, ej beslutade** (grillas/landas vidare): grillnings-disciplinens exakta mekanism i Code [LÖST — Del 6];
  migrerings-kartan (vad flyttar/retireras/arkiveras); issues-verktygsval; CONTEXT.md-placering [LÖST — Del 7; artefakten heter ORDLISTA.md];
  ADR-harmonisering mot Pococks 3-villkors-test; PRD↔byggplan; prototype; diagnosing-bugs; tracer-bullet (formalisera som ledord — ersätter befintlig 'Landning'-praxis).
  Konkordansen (Del 1 leverabel 1) materialiseras inkrementellt ur fork-Delarnas klassningar och samlas i ADR-068-texten vid Accepted-graderingen.

### Konsekvenser

- *Förenkling:* 4-zoners-output + Chat→Code handoff-kontrakt + Chat-halvor retireras — de fanns bara för
  reläet. Färre rörliga delar.
- *Migrerings-skuld:* värdebärande Chat-discipliner måste in i Code:s modell innan apparaten pensioneras —
  annars stryks rigor på köpet. Egen landning (Beslut p.6).
- *Kodbas-grundat design-arbete* (plan-djupa-moduler) körs nu i Code mot live disk, ej i Chat mot index.
- *Bevaras:* all governance (lifecycle, CI-grindar, frontmatter-policy, count-tokens); alla filer förblir
  governade git-artefakter; tre-aktörs som arkiverad fallback tills två-aktörs bevisat.
- *Namngiven risk:* i två-aktörs är Marcus enda mänskliga kontroll på Code. Mildras av starka slingor,
  §3.1-STOPPA, och den mätta prövotiden med arkiverad fallback.
- *Residual research-koll:* bedömd EJ nödvändig som lås-villkor (senior-beslut, S47) — beläggen pekar
  samstämmigt och den mätta prövotiden + reversibiliteten är den verkliga garantin.
- *Supersession-fotavtryck (uppdaterat S47 efter cross-repo-inventering):* ADR-068 reverserar ADR-041 i sak (kollapsar tre-aktörs-upplägget — Chat-ytan pensioneras och Marcus reläroll upphör, men Marcus behålls som enda mänskliga aktör; ej bara dess default). Vidare berörs, verifierat mot disk: **ADR-043** — dess två-yts-premiss upphävs (Chat pensioneras → lifecycle kollapsar till Code-sidig; paus/resume migreras till Code, Del 3 Decision A). **ADR-042** — code-role-discipline överlever och förstärks som hemvist för migrerad rigor, men §4.1/§5 amenderas kirurgiskt (ej superseder, Del 3 Decision B). **ADR-034** — skill-arkitekturen amenderas (Chat-halvorna retireras; Code-halvorna står och absorberar). Alla berörda ADR:er (041/042/043/034) bor i spoke docs/decisions/ — samma plats ADR-068 graderas till vid Accepted, vilket håller supersessions-kedjan samlokaliserad. ### Decision A — paus/resume migreras till Code (ej bara bortkoppling)

paus/resume är idag Chat-only utan Code-motpart (ADR-043-asymmetrin). De bär kontinuitets-*värde*

## Del 5 — Enabling-detour: lychee-cache-flake (väg A)

**Rotorsak:** Steg 0-vendoringen (`151817c`) blev CI-röd (run `28601497591`), men **inte** av vendoringen —

(429) hade cachats som fel; lychee-cachen (`--max-cache-age 1d`, restore-key-prefix `cache-lychee-`) var
förgiftad → hade fällt vilken commit som helst mot main tills cachen åldrats ut.

**Triage (ADR-053):** blockerade landnings-verifiering + utanför Steg 0-scope → STOPPA → eskalerat till
Marcus. **Väg A kvitterad.**

**Åtgärd (`d1cc931`, egen enabling-detour-commit):**

- `--cache-exclude-status '429'` i lychee-args — transient rate-limit cachas aldrig som fel (klass-fix,
  ej bara denna URL). LÄS-verifierat: lychee-action v2.8.0 buntar lychee **v0.23.0**, som stödjer flaggan
  (`lychee-bin/src/options.rs:493`, exempel-syntax `429, 500..502`) → ingen version-bump.
- Cache-nyckel-prefix bumpad `cache-lychee-` → `cache-lychee-v2-` (key + restore-keys + save) =
  deterministisk engångs-kallstart av den förgiftade cachen; v2 behålls framåt.
- **`.lycheeignore` orörd** — add-only-policyn intakt (väg B ej vald; sparad som motiverat nästa steg
  om länken visat sig persistent-flaky, vilket den inte gjorde).

**Utfall:** run `28603191157` **grön** (röd `28601497591` → grön). lychee `🚫 Errors 0`, gitlab-länken
