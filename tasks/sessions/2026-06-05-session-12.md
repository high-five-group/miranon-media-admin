## Del 2 — Inkrement 2: Code-halva (session-start + create-session-doc)

Inkrement 2 utökade hub-pluginets `session-start`-skill med en sessionsdok-skapande-
gren och landade pluginets första referensfil (progressive disclosure per Agent-Skills-
standarden, `references/`-konventionen). Plugin-version 1.2.0 → 1.3.0, publicerad via
marketplace marcus-hub.

**Byggt (hub-repo, commit `8db2b5a`):**

- `session-start/SKILL.md`: ny mager `### Skapande-gren`-subsektion (gren-villkor start
  vs resume, ADR-043 beslut 5) + forensik-rad i `## Output-format`. Stegen ligger inte i kroppen.
- `session-start/references/create-session-doc.md` (NY, 13 steg inkl. post-skapelse-
  forensik): pluginets första referensfil. Empirisk grund: Session 12 inkrement-0-födelse
  + Session 6.6.6 mini-5. Bakar in fil-mekanism-fakta inkrement 0 verifierade (sessionsdok
  ej hook-governat, utanför markdownlint-globs, tom Vale-BasedOnStyles) + datum-portabilitet
  (GNU `-d` vs BSD `-v+3m`) + per-jobb-CI-verifiering.
- `plugin.json`: 1.2.0 → 1.3.0. 4-skill-invariant bevarad (create-session-doc bor i
  session-start, ej 5:e skill — ADR-043 beslut 3).

**Marketplace-drift-heal (hub-repo, commit `3f11ed2`):**

- Pre-existing drift (Code-fångst): `marketplace.json` `plugins[0].version` + `metadata.version`
  stod kvar på 1.1.0 (bumpades aldrig vid 1.1.0→1.2.0). Belägg-grundat beslut (git-historik:
  `e8aadf0` bumpade alla tre version-deklarationerna i lockstep) → båda fälten speglar
  plugin-versionen i denna enkel-plugin-hub → båda → 1.3.0. Återställer `plugin.json ↔
  marketplace`-överensstämmelsen som `claude plugin tag` förväntar.

**Re-install + verifiering:** hub pushad (`16a4e9f..3f11ed2`); `claude plugin update` krävde
två icke-uppenbara steg (`marketplace update marcus-hub` för cache-refresh FÖRE `plugin update`,
+ marketplace-kvalificerat namn `marcus-system@marcus-hub`). Disk-verifierat: cache `.../1.3.0/`
skapad, referensfil närvarande, `claude plugin list` = 1.3.0 enabled, 4 skill-kataloger,
install-record 1.3.0.

**Restart-caveat (ärlig avgränsning):** 1.3.0 installerad + enabled + verifierad på disk. Den
körande Code-sessionen bär fortfarande 1.2.0-skillen i minnet — skapande-grenen blir live-aktiv
för modellen först efter Code-omstart. Leveransen (på disk) är komplett; minnes-aktivering i
körande process är restart-bunden, inte ett fel.

**Fynd → hub-governance-tråden:** ingen mekanism håller `plugin.json` ↔ `marketplace.json`
(`plugins[].version` + `metadata.version`) i synk → de drev obemärkt 1.1.0→1.2.0. Samma klass
som hub-governance-luckan (marcus-system saknar markdownlint/CI/frontmatter-hook). Bärs till den
dedikerade hub-governance-sessionen, ej fixad här.

**Lesson-kandidater (skördas formellt vid lessons-skörd, L77+):**

- Re-install från git-marketplace kräver `marketplace update <hub>` (cache-refresh från remote)
  FÖRE `plugin update`, + marketplace-kvalificerat plugin-namn (`<plugin>@<marketplace>`; bart
  namn → "not found"). [UNIVERSAL] — varje framtida plugin-bump.
- Prompter med inbäddad shell får ej anta GNU coreutils på darwin (`date -d` saknas; BSD
  `date -v`). [UNIVERSAL] — redan förebyggd i create-session-doc steg 5.
- En version-bump som lämnar marketplace-manifestet på gammal version är en *ofullständig* bump;
  version-ytan inkluderar marketplace-entryt. [UNIVERSAL]-kandidat.
