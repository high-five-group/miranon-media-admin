### Klassning

**Issues-substratet: ADAPT.** Matts tracker-arkitektur (pluggbar issue-tracker
som sanningskälla bakom to-prd/to-issues) adopteras; instantieringen adapteras
till vår hårda K1-grind (ADR-068 p.7: governade filer-i-git) via **Backlog.md**
(`MrLesk/Backlog.md`, MIT, TypeScript) på Matts eget lokal-spår. "Matts
upplägg" ÄR den pluggbara trackern — GitHub Issues är hans vanligaste
*instans* ("Bestäm var arbetet bor (ofta GitHub Issues)"), inte modellen.

### De sex låsta besluten (grenarna A–F)

1. **A — Verktygsvalet: Backlog.md.** Enda kandidaten med ✓ på alla åtta
   kriterier (K1 filer-i-git … K8 DoD-arv). Bär Del 12:s kontraktspunkter
   nativt: Överordnat ärende = `--parent` · Blockeras av = `--dep` ·
   acceptanskriterier = `--ac` · AFK-märkning = `-l ready-for-agent` ·
   DoD-arv = `definition_of_done`-config (kontraktspunkt iii — ingen annan
   kandidat har den). Uppfyller #203-primitiverna (stabila `task-N`-ID:n,
   list/filter/search/show, `--plain`-utdata). Mognad: ⭐5,9k, MIT, aktiv
   (push 2026-07-02), zero-config, ingen server, `autoCommit=false` +
   `bypassGitHooks=false` default. Förstaparts-stöd ur Matts eget repo
   (live-verifierat i grillningen): (i) out-of-scope-doket
   (`.out-of-scope/mainstream-issue-trackers-only.md`) klassar Backlog.md i
   mainstream-klassen med GitHub/GitLab ("broadly known, widely used, well
   past the experimental phase") medan "a brand-new agent-focused tool with
   a few hundred GitHub stars is not" (dex ⭐300 avvisad, deras #99);
   (ii) deras #203 stängdes av Matt själv med "set it up yourself during the
   setup skill" — CLI-backad lokal tracker är setup-vägens avsedda bruk;
   (iii) hans setup-svit erbjuder lokal-spåret förstklassigt
   (issue-tracker-local.md).
2. **B — Hemvisten.** Mekanismen (adapterade to-prd/to-issues, mallar,
   DoD-defaults, etikettvokabulär) → hub-pluginet vid fork 4-bygget, ärvs av
   alla spokar — STÅENDE beslut fork 1 beslut 3 TILLÄMPAT (ej omprövat);
   samma mönster som ORDLISTA.md (mekanik i hub, instans i spoke; framtida
   spokar får egna instanser gratis — dubbel-output-visionen). Instansen
   (katalog + config + kort) → per repo; plats: **`backlog/` toppnivå**
   (verktygs-default = idiom + portabilitet; ren separation från
   tasks/-maskineriet; synlig katalog, T01-legibility). Binären = global
   maskin-installation (kommandot dokumenteras i Del 3; mekanism-dok vid
   fork 4-bygget).
3. **C — Governing-fit: medveten grind-exkludering, klassen "verktygsägd
   yta".** Disk-verifierat i STEG 0: `backlog/` ligger UTANFÖR samtliga
   grindar redan — markdownlint-globs, Vale-kataloglistor, frontmatter-14
   (exakt path), lifecycle-scope OCH lychee-args (docs/tasks/sessions/
   threads/rot-md) — **noll config-ändringar krävs** (L225-bivillkoret
   orört). Rationale: korten är verktygsägda koordinationsartefakter
   (Backlog.md äger frontmatter-schemat, muterar filerna via CLI);
   prosa-lint på dem vore att grinda ett annat verktygs output, med
   lint-rött i arbetsloopen som pris; precedensklass = pocock-korpusen
   ("extern korpus, ej vår prosa"). **Exkluderad ≠ ogovernad:** varje
   kort-ändring är en git-commit genom våra hooks (`autoCommit=false`,
   `bypassGitHooks=false`), CI-detect klassar kort-commits docs-only,
   och kortens semantiska grind är fork 4:s mallar + DoD-defaults +
   verktygets egen frontmatter-validering (#203:s hela poäng). Ev.
   legibility-kommentarrader i configar → fork 4:s grind-landning med
   testsvit (L225).
4. **D — ADR-baren: S47-vägen.** Ärlig prövning: villkor 2 (överraskande
   utan kontext) + 3 (verklig avvägning) JA idag; villkor 1 (svårt att
   återställa) mognar till JA i koherens när fork 4-bygget hårdkodar
   CLI-formen i skills (Matts out-of-scope-doc ordagrant: "every backend
   hard-codes a CLI shape into the skills … permanent maintenance
   surface"). Timing mot ADR nu: minimal-testet okört (tracer-bullet-logik:
   validera före lås), ADR-068 själv Proposed (barn graderas inte före
   förälder), fork-svit-precedensen håller konkordansen samlad. → Del 2 bär
   beslutet; materialisering vid ADR-068 Accepted-gradering, där ev. EGEN
   ADR (verktygsberoende = ADR-029/031/035-klassens territorium) beslutas i
   den akten.
5. **E — Minimal-testets form (exekveras som Del 3).** `npm i -g backlog.md`;
   `backlog init` med exakt git-diff-inspektion; K2-kedje-kort (förälder +
   barn med `--parent`/`--dep`/`--ac`/`-l ready-for-agent`; dummy-innehåll —
   riktiga specar kräver fork 4:s mallar). Åtta godkänt-kriterier:
   (i) init rör endast `backlog/` (+ explicit godkänd config-fil),
   (ii) förälder/beroende/etikett/AC fungerar per CLI-dokumentationen,
   (iii) `--plain` deterministiskt agent-läsbar, (iv) lokala grindar ser
   inte `backlog/`, (v) pre-commit-hooken rör inte korten, (vi) CI grön PER
   JOBB med docs-only-klassning, (vii) `backlog board` + `backlog browser`
   visar tavlan (Marcus översikts-kvittens), (viii) reverseringsvägen
   verifierad (`git rm -r backlog/` + revert + `npm rm -g backlog.md`).
   FAIL på någon punkt ⇒ öppen rivning av gren A med evidensen redovisad
   (fork 3-precedensen: låst beslut är inte immunt mot evidens).
6. **F — Gränsen + DEFER-fördelningen.** `tasks/todo.md` (dagslogg),
   tråd-registret (trådar) och sessionsdok (samtal/beslut) behåller sina
   roller orörda; substratet tar ENBART den bärarlösa rollen framåtriktade
   arbets-specar (PRD-kort + skivor). Ingen migration (låst bivillkor).
   Riktiga arbets-specar föds i substratet FÖRST när fork 4-bygget landat —
   tills dess gäller interim-läget (Del 12 beslut 2). Dummy-korten =
   demo-tavla, städas vid fork 4-bygget. **DEFER → fork 4-bygget:**
   PRD-kort-mallen + issue-mallen som Backlog.md-flöden · DoD-defaults
   (`definition_of_done`) · etikettvokabulären (mappningen färdig i
   korpusens triage-labels.md) · adapterade to-prd/to-issues → hub ·
   kö-prioriteringsordningen (Del 12 vii) · agent-instruktionsrad
   (CLAUDE.md/AGENTS.md-klass, hub-mekanism) · QA-kort- +
   uppföljnings-issue-mönstren · ev. grind-legibility-rader (L225-landning).
   **DEFER → do-work-landningen:** do-work-skillen (grillas mot
   code-role-disciplinen, Del 16 F1) · TDD-adaptionen (Del 15) ·
   etikett-DRIVEN plockning som operativ kö · AFK/Ralph-loop + sandbox
   (T57+).

### DECLINE (L30-durabla skäl — inget återföreslås oinformerat)

- **GitHub Issues-molnspåret** (grillningens fördjupningsgren, Marcus-vägd):
  valet av moln hade offrat (1) spec-trailen — muterbar moln-state utan
  commit-historik; `git log --grep`-forensiken och Pre-K-passet blinda för
  specarna; (2) atomisk kort↔kod-koppling (L225-klassen omöjlig);
  (3) CI-grindbarhet + nytt nätverks-/secret-beroende i CI (K7;
  .lycheeignore-klassens GHA-nätverksevidens); (4) klon-kompletthet —
  do-work-kärnan hade krävt nätverk + auth per varv; (5) ADR-068-koherensen:
  state-utanför-disk är exakt vad Chat-pensioneringen rev. ERKÄNDA
  moln-vinster (ärligt redovisade): alltid-på-åtkomst från annan enhet,
  notiser, PR-korslänkning ("Fixes #N"), extern-kollaboratörs-UI;
  agent-ergonomin hade INTE offrats (gh är förstklassig CLI).
  Återväckningsvillkor: externa utvecklare i repot → frågan väcks på nytt
  som medvetet beslut. Matt "löser" inte offren — han HAR dem inte: hans
  specar är operativt förbrukningsmaterial (han grindar kod, inte specar);
  vår konstitution gör arbets-specen till governad trail-artefakt
  (kontinuitets-arkitekturen). Samma fråga, olika kontrakt → olika svar.
- **Noll-optionen** (egen markdown-konvention + tunn egen CLI; Matts
  .scratch-form): #203 ur Matts eget repo visar konvention-utan-CLI som
  icke-agent-duglig (ingen deterministisk återfinning/filtrering, ad
  hoc-frontmatter-parsning, korruptionsrisk); egen CLI = egen kodbas utan
  andra användare — över-engineering-vaktens spekulationssida — när ett
  mainstream-verktyg uppfyller alla åtta kriterier.
- **steviee/git-issues** (⭐13, 1 HN-poäng, solo, tyst sedan 2026-05-06):
  formmässigt korrekt (md+YAML i `.issues/`, ingen server) men exakt
  klassen Matts out-of-scope-doc avvisar — fel risk för substratet som ska
  bära hela spec-kedjan.
- **driangle/taskmd** (⭐49): riktigt verktyg (md+YAML, CLI, Claude-plugin,
  MCP) men `taskmd init` skapar `tasks/` — direktkollision med vårt
  tasks/-maskineri; konfigurerbart men idiom-stridigt i varje framtida
  spoke; K6 tunn.
- **git-bug** (⭐9,9k, aktivt): lagrar issues som git-OBJEKT — README:
  "objects in a git repository (*not files!*)" — K1-fail mot ADR-068 p.7.
  Ärligt prövad, föll på den hårda grinden.
- **beads** (⭐25k, aktivt): Dolt-SQL-databas som sanningskälla
  (`.beads/embeddeddolt/`); `issues.jsonl` uttryckligen "an export for
  viewers and interchange, **not the source of truth**" — K1-fail; server-
  lägen och MySQL-portar på K7-sidan. Imponerande projekt, fel form.
- **dspinellis/git-issue**: `.issues` är egen inbäddad git-repo som enligt
  README ska GITIGNORES i projektet + eget filformat (beskrivnings-/
  tagg-filer, ej md+frontmatter) — K1-fail i vårt repo + K5-fail; ~9 mån
  sedan senaste push.
- **veggiemonk/backlog**: uppström ARKIVERAD (gh `isArchived: true`, ⭐8,
  sista push 2026-01-04) — K6-fail, struken före djupare prövning.
