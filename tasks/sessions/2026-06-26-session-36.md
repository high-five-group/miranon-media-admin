## Del 1 — Syfte och scope

### Syfte

Session 36 bygger Fas 6g L3 — Spara segment: repots FÖRSTA WRITE i 6g. En sparad segment-regel persisteras som typad JSON i ett nytt dedikerat fält i Segment-tabellen, som tillika är MIGRATIONS-MÅLET för de 9 legacy-formelsträng-segmenten på vägen mot Make-deprecering (ADR-062 beslut 7, rivs ej mitt-i-flykt). Styrande nytt beslut: ADR-065.

### Scope (i scope)

- ADR-065 — segment-regel-persistens (nytt JSON-fält i Segment-tabellen; format; target; migrations-mål-roll; pekar ADR-062 beslut 7 + T16 för Make-vägen).
- Schema-mutation (senare pass) — nytt fält på staging + prod Segment-tabell, additivt, verifierat.
- Write-vertikal (senare pass) — save-EF (fields byggs SERVER-SIDE ur typad regel) + field-allowlists-post (ny operationKey) + 1 deny-test + 1 allow-test (ADR-060) + adapter saveSegment + spara-UI i SegmentBuilder + lista över sparade segment + e2e happy-path.
- Opportunistisk städning — "Session 36"-mislabel i compute-segment/index.ts:25 + src/lib/segment-taxonomy.ts:8 (rättas i write-passet när filerna ändå rörs).

### Floor (icke förhandlingsbart)

- Segmentformel / Antal i segment / Beräkna-knappen lämnas ORÖRDA (Make-vägen, rivs ej mitt-i-flykt).
- Fält-skrivbarhet verifieras mot data-model FÖRE write (L140); formel/rollup/lookup/button/lastModified = aldrig skrivbara.
- Fält-namn teckenexakt mot live-schema (L194 STOPPA-grind).
- Consent-fält (Ej godkänd för mailutskick) bärs, filtreras ej — konsekvent med L1/L4.
- Deny-by-default allowlist-grind.
