## Del 3 — DEL 2-sidotråden: lesson→grind-wiring, T11b-discovery, arkivering

### Hur det började

DEL 2 skulle wira två befintliga test-suiter (`test-check-frontmatter.sh` + `test-check-public-checklists.sh`) i `ci.yml` `lint`-jobbet — uppvärmning enligt ADR-039:s lesson→grind-princip. Forensisk pre-pass (DEL 0) bekräftade att båda sviterna passerade grönt lokalt på macOS (14/14 + 5/5) och att fetch-depth-carrier-invarianten inte trippades av wiring-formen.

Push av wiring (commit `e25f2fe`) failade dock på CI: T11b inom `test-check-frontmatter.sh` failade med `❌ T11b cd failed`.

### Eskaleringen — fyra rundor

Sidotråden växte i fyra rundor, var och en lokalt försvarbar:

1. **Hypotes (a)**: loose→pack-race mellan commit-loop och clone. Mitigering: `git repack -ad` (commit `50b91e6`). Empiri: 8/10 grönt — *otillräckligt*, hypotes falsifierad.

2. **Web-research-pass** (research-före-fix-disciplin). Förstapartskälla git-gc(1) matchade felmodet exakt: gc kan deleta object som pack-objects samtidigt läser. Reviderad hypotes (b): auto-gc + maintenance.auto-race.

3. **Mitigering**: `git config gc.auto 0` + `git config maintenance.auto 0` i `setup_repo()` (commit `32c953f`). Empiri: 10/10 grönt på samma commit. Fixen verifierad.

4. **Attribuerings-försök blockerades** av separat artefakt: draft-PR isolerings-runda failade *innan* T11b körde, eftersom `pull_request`-mode-checkout (`refs/pull/N/merge`) gav annan committer-datum än branch-tip → `check-frontmatter`-validatorn failade. Attribuering mellan `gc.auto` och `maintenance.auto` återstår obegripen — dokumenterad öppet i scriptet per L53 (verifierad fix utan attribuering ≠ begripen determinism).

### Meta-frågan + arkivering

Vid eskaleringens fjärde runda uppstod en deterministisk CI-state-drift på huvud-grinden `check-frontmatter` som inte var sidotråds-skapad — `git log -1 --format=%cs` returnerade annat datum i CI än lokalt på 4 av 9 styrande docs. Diagnosen (DEL 2 av DEL 5b lesson L60-källan): shallow-fetch-cutoff över commit-tunga repo-fas — 5 av 9 styrande docs utanför fetch-depth 100.

Det utlöste meta-frågan: *är detta fortfarande Session 9-scope, eller har sidotråden glidit?* Code:s rapport hade redan börjat formulera den frågan ("att forcera DEL 3-6 ovanpå CI-drift-research vore 11/10-glidning, inte 11/10-leverans"). Beslut: **rulla tillbaka wiring-commiten** (commit `fba2624`) och flytta lesson→grind till egen framtida session. T11b-fixen (commit `32c953f`) behålls i scriptet som vilande — verifierad mekanism + förstapartskälla mot reellt race; att kasta vore att kasta evidens. Dokumenterat med "dormant pending lesson→grind session"-not (commit `af6b05d`).

### Lärdomar (skördade till L57-L61)

- **L57**: Lesson→grind-wiring kan exponera latenta CI-only-defekter. Behandla första-gångs-wiring som upptäcktsoperation, inte mekanisk dependency.
- **L58**: Web-research ska peka ut *vilken* mekanism-familj som matchar, inte bekräfta den mest tilltalande hypotesen. Falsifiera först.
- **L59**: Verifierad fix utan attribuering ≠ begripen determinism. Erkänn obegripenhet öppet.
- **L60**: CI-grindar som läser git-metadata kan vara mode-känsliga (push vs PR-merge). Validera mot båda om mode-portabilitet förväntas.
- **L61**: Lokalt försvarbart + lokalt försvarbart = aggregat scope-eskalering. Stanna vid tredje beslutet i en sidotråd och ställ meta-frågan.

## Del 4 — DEL 2.5: fetch-depth-invariant bumpas 100→250

### Hur det började

DEL 2-revert (sidotråden, se Del 3) lämnade main röd: huvud-grinden `check-frontmatter` failade på 4 av 9 styrande docs med `'2026-05-17' driftar från git log '2026-05-18'`. Code:s första hypotes var dagsskifte-drift mellan 2026-05-28 (grön) och 2026-05-29 (röd). 5/5 reruns på commit `ec8f4cd` bekräftade deterministisk drift — inte flapping.

### Diagnosen (mekanism namngiven)

Code:s rerun mot Session 8:s sista gröna commit (`32c953f`) idag *passerade*. Det falsifierade dagsskifte-hypotesen och pekade på något kod-relaterat — specifikt commit-skillnad mellan `32c953f` och `af6b05d`. Forensik:

| Fil | Senast-rörande commit | Commits till HEAD | Inom fetch-depth: 100? |
|---|---|---|---|
| KVALITETSDEFINITIONER-11-REACT.md | 7ac2971 | 113 | ❌ utanför |
| SECURITY-SPEC.md | 91b6337 | 115 | ❌ utanför |
| hur-systemet-funkar.md | 91b6337 | 115 | ❌ utanför |
| data-model.md | 91b6337 | 115 | ❌ utanför |

Lokal simulation av `clone --depth=100` reproducerade CI:s output exakt (2026-05-18 istället för 2026-05-17). Mekanismen: **shallow-fetch-cutoff över fetch-depth 100** på commit-tunga repo-fas. `git log -1 --format=%cs -- <fil>` returnerar commit-datum för senast-NÅBARA commit som ser ut att röra filen i shallow-historien — inte den faktiska senaste edit-commiten.

Risken var prognosticerad i `ci.yml`-kommentar från Session 6.7 K0.S2: *"Djup 100: commit-tunga sessioner kan skjuta orörda governing-docs förbi djup 50; 100 ger reell marginal."* Session 7 K0.S2 bumpade 50→100 av exakt samma anledning. Session 9 ackumulerade 113-115 commits sedan governing-docs senast rördes — marginalen var förbrukad.

### Beslut: konstitutions-underhåll, inte sidotråd

Detta var *inte* fortsatt sidotråd. DEL 2 var arkiverad. Detta var pre-existing huvud-grind som träffat sin dokumenterade tröskel — ADR-039:s invariant-värde-översyn-territorium. Senior-ompositioneringen: **fix:a det nu och rent, inte skjuta till framtida session**. Annars rapporterar varje framtida push röd CI tills någon annan tar det.

Två kandidat-mitigeringar avvägdes:

- **Manuell bump av `updated:`-fält på de 4 drabbade filerna**: avvisades hårt. Skulle skriva *fel datum* i frontmatter (filerna ändrades 2026-05-17, inte 2026-05-29). Aktiv lögn i styrande dokument oavsett att mekanismen är namngiven.
- **Bump fetch-depth-invarianten 100→250**: valdes. Konstitutions-underhåll inom ADR-039:s mönster, mönsterförstärkning av Session 7 K0.S2 (50→100).

Bump-värdet 250 grundades empiriskt: commits-per-session-takt × marginal-i-sessioner. Sedan Session 7-bumpen har värsta filerna ackumulerat 115 commits över 2 sessioner = ~55 commits/session-takt. 250 ger marginal ~135 commits ≈ 2-3 sessioner. 345 vore overshooting (3× värsta filen men 6× per-session-takten — vi vet inte än om takten är stabil); 230 vore snävare än vad vi just gav oss för 2 sessioner sedan.

### Bumpens yttringar — 11 ändringar atomiskt

Per L63 (konstitutionellt invariant-värde har flera yttringar; alla bumpas atomiskt eller någon ljuger om världen):

- 4 ci.yml-jobb: `fetch-depth: 100 → 250`
- `.frontmatter-policy.conf`: `FRONTMATTER_MIN_HISTORY_DEPTH=100 → 250`
- `scripts/check-frontmatter.sh` default: `${FRONTMATTER_MIN_HISTORY_DEPTH:-100} → :-250`
- ADR-029 + ADR-030: additiva erratum-blockquoter (frusen besluts-text rörs ej, L53)
- ADR-039: ny erratum-iteration som dokumenterar 100→250-bumpen med empirisk grund och rationale
- T11b-testet: edge-case-värden bumpade från 100 till 250 (annars ljuger testet om sin testperson — secondary impact fångad av pre-flight, L63)

### Pre-flight + verifiering

Pre-flight verifierade två kritiska mekanismer empiriskt:

1. **Multi-blockquote-tolerans**: `check-fetch-depth-invariant.sh` greppar `> **Korrigering` + matchar mot live-värdet. ADR-029 + ADR-030 har nu *två* erratums (Session 7 K0.S2 nämner 100, Session 9 nämner 250). Bekräftades att skriptet matchar nya 250-värdet i multi-line output utan att gammal blockquote stör.

2. **Carrier-invariantens räckvidd**: alla 6 levande bärare verifierade som design-intern konsistens. Skriptet hårdkodar inte värdet 100; det greppar dynamiskt ur `ci.yml`. Bumpen är därför ren värde-skiftning utan struktur-edit.

### Lärdomar (L62-L63)

- **L62**: Invariant-värde-översyn är periodisk; en grön invariant-grind säger att invarianten håller, inte att värdet är rätt.
- **L63**: Konstitutionellt invariant-värde har flera yttringar (live-bärare + ADR-erratums + test-suite); alla bumpas atomiskt eller någon ljuger om världen.

## Del 5 — Roll-arkitektur Chat/Code/Marcus etablerad i båda ytor

### Bakgrund

Tidigt i sessionen (mellan DEL 1 och DEL 2) fångade Marcus tre symptom hos Chat:

- Bröt en-block-konventionen (Code-prompter levererade som prosa + lösa kodblock).
- Missade att läsa hub-CLAUDE.md i sin helhet vid orientering (sökte topiskt och kallade det orientering).
- Saknade roll-medvetenhet för det vardagliga arbetet (ADR-041 löste sessionsavslut men inte mellansession-flödet).

Marcus' formulering: *"Session 10 måste FUNKA sömlöst. Du och Code måste direkt förstå era roller och hur vi (alla tre) interagerar/samarbetar med varandra."* Det blev sessionens andra arkitekturtema.

### Forensik först (det fanns redan — men hade tappats)

Sökning i projektkunskapen visade att 4-zoners-mallen + STOPPA-OCH-FRÅGA-formatet hade etablerats i hub-CLAUDE.md commit `c06d3ff` (Session 6.5). Lessons K2.13 + K2.14 dokumenterade *exakt* samma fel som inträffade nu — en Chat-iteration uppfann nytt format parallellt med befintlig regel. Session 6.7 K6-refactorn lyfte ut formatet ur hub-CLAUDE.md (klassningstabellen K2 routade det till "Chat-side / Project Instructions"), men routningen genomfördes aldrig. Plus att Session 6.7:s T3-beslut ville extrahera STOPPA-formatet till en `code-stoppa-format`-skill som deferrades i K5 och aldrig byggdes. Dangling pointer i hub-CLAUDE.md.

Sammantaget: 4-zoners-mallen levde *ingenstans aktivt* — utlyft ur CLAUDE.md, aldrig landad i sitt nya hem. Code:s forensik hämtade den verbatima texten ur commit `2a4a8c7^` så designen byggdes mot fakta, inte minne.

### Research-före-arkitektur

Detta var arkitekturbeslut → research-disciplinen gällde fullt ut. Tre branscher konsulterade, alla konvergerade entydigt mot **explicit roll-arkitektur framför implicit kontrakt**:

- **Anthropic Engineering (Boris Cherny)**: CLAUDE.md är konstitutionen, läses automatiskt vid sessionsstart, "supreme law" som överrider tillfälliga prompter. Optimal storlek ~100-200 rader. Gyllene regel: *"Anytime we see Claude do something incorrectly, we add it to CLAUDE.md so it doesn't repeat next time."*

- **Multi-agent LLM-litteratur**: Roller är "highest-leverage investment". Safety guardrails och arbetsdelningsregler ska vara *"layered and explicit, rather than implicit side effects of prompts."*

- **Google SRE**: Decision rights ska vara *explicit* för att undvika att en aktör blir powerless eller bottleneck. RACI-mönstret är universellt. Explicit handover-protokoll ("Du är nu incident commander, okay?") är standard.

Min initiala lutning ("lita på implicit kontrakt") falsifierades trefaldigt av research:en. Det är L_AAA-mönstret (slutsats utan empirisk grund) som research-pass:et fångade.

### Beslut: split mellan ytor (DEL 3 + DEL 3.5a)

Per ADR-034:s leveransyte-modell: disciplin levereras per yta. Roll-arkitekturen manifesteras därför i båda — *en* arkitektonisk leverans i två ytor:

- **DEL 3 — Chat-side (spoke Project Instructions)**: Fyra nya sektioner i `project-instructions/miranon-media-admin.md`: ROLL-ARKITEKTUR (princip), CHAT-OUTPUT 4-ZONERS DISCIPLIN (verbatim ur Session 6.5-commiten), SESSIONSSTART (orientering före design), SESSIONSAVSLUT (Chat dirigerar, Code bekräftar — pekare till ADR-041).

- **DEL 3.5a — Code-side (hub-CLAUDE.md)**: Ny H2-sektion `## Roll-arkitektur — Chat, Code, Marcus` mellan rad 41 ("Hur Marcus jobbar") och rad 45 ("Instruktioner"). Pekarstil per hub-prejudikatet (PRINCIPER inline, HUR delegerat). Pekare till `plugins/marcus-system/skills/session-start/` för läs-orientering + flagga att full code-roll-disciplin etableras i Session 10 som egen skill.

### Vad varje aktör är (explicit decision rights)

- **Chat**: designar och dirigerar (arkitektur, prompt-design, lessons-skörd). Tar *inte* fil-ops.
- **Code**: utför mot disk (LÄS → RAPPORTERA → PLANERA → IMPLEMENTERA → VERIFIERA, transparens-rapport, STOPPA-grindar). Tar *inte* arkitekturbeslut på eget bevåg.
- **Marcus**: beslutar, pushback:ar, prioriterar. Klient-mässig kanal mellan Chat och Code (de har ingen direktkanal). Är *inte* review-loop för triviala detaljer.

Empiriska fångst-rater (Session 8-data, refererade i båda sektionerna): Chat-self-review ~9 %, Code-transparens ~64 %, Marcus-pushback ~27 %. Det är skälet till att roll-arkitekturen *behövs* — extern fångst är där den verkliga disciplinen sitter.

## Del 6 — DEL 4: session-end-skill reframe + plugin 1.1.1 → 1.2.0

### Bakgrund

Skillen krympte 115 → 96 rader (-17 %). Hub-rutinens 7 numrerade steg + Spoke-rutinens 15 steg (båda "read-do autonomt utförande") ersattes av:
