## Del 1 — Scope för Session 6.6.7

### 1.1 — shellcheck-strict CI-grindvakt

CI-step i lint-jobbet, efter check-frontmatter (analogt med ADR-030 §
Konvention för framtida CI-utvidgningar). Command:

```bash
shellcheck \
  --severity=style \
  --enable=all \
  scripts/*.sh \
  .githooks/* \
  .checklist-policy.conf \
  .frontmatter-policy.conf
```

`--severity=style` fångar warnings (default = "warning" skip:ar
"style"-level). `--enable=all` aktiverar optional checks (SC2310-SC2312
m.fl. som är default-disabled).

Strict-mode: 0 warnings + 0 errors = exit 0. Annars exit 1.

### 1.2 — Retroaktiv fix av pre-existerande warnings

Baseline-pass FÖRE CI-aktivering: kör shellcheck mot scope och fixa
warnings empiriskt. Förväntad fyndmängd: 0-10 warnings (post-K7.B +
K7.5.4-polish). Eventuella nya fynd kategoriseras per ADR-022 3-
kategori-modell.

### 1.3 — ADR-033 (egen ADR-domän)

Per ADR-029 § Konvention. ADR-033 dokumenterar:

- Beslut: shellcheck-strict som CI-grindvakt
- Scope-definition (filer + severity-nivåer)
- Konsekvenser: nya bash-scripts måste vara shellcheck-strict från start
- Spårbarhet: K7.B-defer-flaggor + K7.5.4-lesson + 6.6.7-implementation

## Del 2 — Strategi-alternativ

### Alt A — shellcheck som CI-step i lint-jobb (rek)

Analog till check-frontmatter + check-public-checklists. Ny step i
ci.yml lint-jobb efter check-frontmatter. Snabb (<5s), körs alltid.

### Alt B — Pre-commit + CI dubbel-gate

Pre-commit hook kör shellcheck lokalt + CI verifierar. Dubbel-gate
fångar tidigare men ökar local-friction. Sannolikt över-engineering
eftersom shellcheck är snabb och bash-scripts ändras sällan.

### Alt C — Bara CI-step

Single-gate som Alt A. Skiljer sig bara om Marcus aktivt väljer att
inte ha lokal körning.

**Rek: Alt A.** Skäl: konsekvent med ADR-030-mönster (check-frontmatter,
check-public-checklists). Branschpraxis-pattern.
