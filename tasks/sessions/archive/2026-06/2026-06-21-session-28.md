## Del 1 — Syfte och scope

Session 28 bär T19 — författandet av den saknade fjärde reference-ytan:
app↔Airtable-INTERAKTIONS-dokumentet. Idag finns tre reference-ytor
(data-model.md = blandad uppgiftskarta; airtable-constraints.md =
plattform-migrationsspec; hur-systemet-funkar.md = mänsklig affärslogik). Ingen
samlar app↔Airtable-KONTRAKTET: vilka fält varje Edge Function läser/skriver,
mappningar, länkfält-filter-mönster, hårdkodade event-värden (create-registration:s
'Event-17'), och fällorna SPECIFIKT i interaktionen (T15-klassen: länk-display ≠
record-ID). Den kunskapen ligger utspridd över EF-källkod, data-model.md:s
EF-sektion, airtable-constraints.md, sessionsdok och trådar.

Byggs FÖRE 6c-resume (Session 27-revision): T19:s primära värde är att vara karta
för den som bygger interaktioner, och 6c är första write-flödet som behöver kartan.
Doket föds som initial/föreskrivande version som 6c sedan validerar och fyller.

Flerpass-projekt (à la airtable-constraints Pass 1/2): Pass 0 (denna — orientering +
scope-design) → författande → granskning mot EF-källkod.
