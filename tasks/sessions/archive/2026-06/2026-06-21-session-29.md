## Del 1 — Syfte och scope

Session 29 tar upp tråd T17 — System-/arbetssätts-dokument. T17-doket är
orkestrerings-infrastruktur för Chat: det vänder Chat-gissning till uppslag för STABIL
samarbets-/process-mekanik och sänker därmed friktionen på PI grundregel 3 (gissa aldrig
— verifiera). Sessionen inleds med Pass 0, en bred read-only kartläggning över båda träd
(hub `~/Repon/marcus-system/` + spoke), plugin-struktur, skills-inventering, governing- och
distributions-mekanik — underlag för att skära dokets FORM, GRÄNSER (T19/T17; SSOT mot
domän-ytor) och FÄRSKHETS-DISCIPLIN (stabil mekanik vs aktuellt tillstånd) FÖRE författning.
Flerpass: Pass 0 (karta) → form/gräns-beslut (Chat) → författning → granskning/wiring.
Större än T16; möjligen flera sessioner.

### Scope (ordnad)

1. Pass 0 — read-only kartläggning (detta pass) → RAPPORTERA till Chat.
2. Form/gräns-beslut (Chat, efter Pass 0): utöka-vs-nytt (avgjort mot disk), T19/T17-gräns,
   SSOT-pekare-vs-ägt, färskhets-disciplin in från start.
3. Författning av T17-doket (kommande pass).
4. Granskning + wiring (governing-beslut, DoD, tråd-kort) (kommande pass).

### Ej i scope

- Författning av T17-doket självt (detta pass är kartläggning, ej författning).
- `hur-systemet-funkar.md`-uppdatering — det är DOMÄN-dok (affärslogik), T21:s territorium, EJ T17.
- `/session-resume` Session 26 → 6c-bygget (EFTER T17).
