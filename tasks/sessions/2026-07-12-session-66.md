### Research-passet (tre parallella web-agenter med citat-krav)

1. **Merge queue-precedenten:** GitHub Merge Queue OTILLGÄNGLIG för
   repot — publikt men **User-ägt** (`gh api`-verifierat; kravet är
   org-ägt publikt eller Enterprise Cloud) — och löser dessutom fel
   problem: köerna ordnar landningen logiskt men kör CI-pipelines
   parallellt (GitLab-dok: "The pipelines all run in parallel"; GitHubs
   eget exempel har pr-1/pr-2-CI samtidigt) → delad staging korrumperas
   ändå. **ADR-073:s orkestrator-ägda serialisering bekräftad som rätt
   form.** Nyckelfynd: Actions-concurrency fick 2026-05-07 `queue: max`
   (upp till 100 väntande FIFO); utan den håller en grupp EN pending
   och AVBRYTER resten — fallgropen som gjorde jobb-nivå-concurrency
   bräcklig när ADR-073-alternativet skrevs. Källor: docs.github.com
   (managing-a-merge-queue, concurrency, about-protected-branches),
   github.blog changelog 2026-05-07 + 2023-07-12, docs.gitlab.com
   merge_trains, bors.tech, graydon2.dreamwidth.org (NRSR),
   matklad.github.io.
2. **Partitioneringen:** ingen branschledare har fil-nivå-affected för
   en single-app (Nx/Turborepo/Bazel/Rush opererar på
   projekt/paket/target-nivå; import-grafer ser inte markdown/spec —
   där vår faktiska kollision låg). Alla fyra agent-plattformarna
   (Anthropic agent-teams, Cursor worktrees, Copilot coding agent,
   Codex cloud) konvergerar på exakt vår form: worktree-isolering +
   disjunkt fil-ägarskap deklarerat i task-designen + PR som
   integrationspunkt — **fasat schema/manuell partitionering ÄR state
   of practice; ADR-073 beslut 1 bekräftat.** Det mekaniska
   check-steget som saknas överallt finns i två billiga former:
   maskinläsbara **claims per kort + intersektions-check** (mekaniserar
   Anthropic-regeln "each teammate owns a different set of files";
   Cassandra-precedent ICSE 2013) och **`git merge-tree --write-tree`**
   som pre-merge-grind (exit 0/1, sido-effektfri; GitHub
   mergeable-API:t + Gitea kör exakt detta; verifierad i lokal git
   2.50.1). Explicit förkastade med källstöd: ML-prediktion (f1
   0,57–0,68 på konflikt-klassen, Owhadi-Kareshk 2019) · full
   beroendegraf (blind för icke-import-ytor) · kontinuerlig spekulativ
   merge (Crystal-kadensen — maskineri för marginell vinst vid korta
   batchar).
3. **SW-/dev-miljö-hygien:** Vites EGNA dokumenterade mönster täcker
   fälla 1+2 (`vite build --mode staging` är förstaparts-exemplet;
   dev 5173/preview 4173-separationen är avsiktlig design — "avoid
   collisions with other tools", Vite 3-bloggen). dotenv i
   playwright.config är ordagrant officiellt Playwright-mönster
   (fälla 3). Post-merge-install är etablerat hook-ekosystem
   (git-scm githooks, post-merge-install/yarnhook; fälla 4 kräver
   OCKSÅ processomstart — Vites optimizer-cache). **Spec-fynd som
   skärper L276:** inte ens 404 avregistrerar en aktiv SW (web.dev
   service-worker-lifecycle + W3C ServiceWorker #204 = wontfix) —
   INGEN passiv självläkning finns; sanering är alltid aktiv (Clear
   site data / getRegistrations→unregister / no-op-SW på samma URL).
   selfDestroying-SW (vite-pwa unregister-guiden) = dokumenterad
   saneringsberedskap, INTE stående staging-läge (sänker
   test-fidelitet; community-förekommande men ej
   förstaparts-kodifierat — tunn precedent öppet deklarerad).
   **Följdfynd:** ADR-073 beslut 7:s B-recept ("preview på 5173")
   skrevs FÖRE fälla 5 och är falsifierat — dev-origin-delning ÄR
   infektionsvägen; revideras till egen port + CORS (slutlandningen).
