## Del 4 — 36.4 merge-dedup levererad (ci.yml-trion KOMPLETT)

### Mekanism (verifierad mot disk+API FÖRE bygget)

På en **main-push** (merge-commit) läser `changed`-jobbet andra föräldern (den
mergade PR-headen). De tunga jobben hoppas ENDAST om:

1. merge-commitens träd == PR-headens träd (`HEAD^{tree} == HEAD^2^{tree}`), OCH
2. den PR-head-SHA:n har en grön CI-run (`gh run list --commit <full SHA>`, L314).

Innehållsadresserad — ingen ny lagringsyta. **Cache-formen är falsifierad och
byggdes aldrig** (L325). Sundheten vilar på merge-grindens strict up-to-date
(ADR-076): en up-to-date-branch ger merge-commit vars träd == PR-head. Mekanismen
verifierades mot faktisk disk + API på merge-commit `bf592ca` (HEAD^2 `f50d514`,
träd `553d4e6…` identiska, grön run `30045193128`) FÖRE en rad byggdes.

**Asymmetrin är medveten:** nyckeln ÄR trädet självt, så dedupen kan bara orsaka
onödig körning, aldrig släppa förbi otestat. **Fail-closed på VARJE avvikelse**
(ingen andra förälder · träd-avvikelse · API-fel · icke-grön run ⇒ full svit).

### Implementation

- **`ci.yml` `changed`-jobb:** dedup-steg (`git rev-parse HEAD^2`, tree-jämförelse,
  `gh run list`) → output `dedup_hit`. Steget grantar `actions: read` (minsta
  grant för API-frågan). Bor i changed-jobbet (redan `fetch-depth: 0`) →
  **fetch-depth-invarianten ORÖRD** (3 bärare, testsvit 7/7).
- **`suite`-jobb:** `if += dedup_hit != 'true'`. Skippad suite → `ci-passed`
  grön (`always()`, L322 intakt — AC#3).

### Bevis (unit-test FÖRE bygget + kontrastbevis-par)

**Lokal unit-test av dedup-logiken mot 6 grenar** (FÖRE ci.yml rördes — samma
metod som 36.2:s span-fix): FALL 1 hit (real merge → `true`) + FALL 2–6 fail-closed
(pull_request-event · ingen andra förälder · icke-grön conclusion · API-fel · tom
conclusion → alla `false`). 6/6 korrekt.

**Kontrastbevis-par (AC#7):**

| Riktning | Run | Test suite |
|---|---|---|
| MISS (PR-event → dedup ej tillämplig) | `30047428027` | KÖRDE (staging RAN, full svit) |
| HIT (main-push, config-ändring) | `30047936570` | **SKIPPAD** — dedup-steg: `Dedup-TRÄFF: träd == a7f60c52^{tree} → tunga jobb hoppas` |

Det avgörande i HIT: merge-commiten var en **config-ändring** (skulle normalt köra
full svit), men Test suite SKIPPADES — enda möjliga orsaken är `dedup_hit=true`.
`ci-passed` grön (skipped tolereras, fail-closed intakt).

**Proof-strategi-not (öppet):** en *riktig* main-push-avvikelse (träd-diff /
icke-grön HEAD^2) kan inte framställas naturligt under merge-grinden — strict
up-to-date + grön required check garanterar just tree-identitet + grön run. Det ÄR
dedupens sundhets-grund. Därför bevisas fail-closed-grenarna uttömmande av
unit-testen (starkare än en enskild miss-run), medan HIT + PR-full-svit bracketar
det reella beteendet.
