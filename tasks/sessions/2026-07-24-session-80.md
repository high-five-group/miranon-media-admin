## Del 1 — Syfte och scope

### Syfte

Göra CI-hastighet till siffror i stället för känsla: leverera **task-36.5
mätskriptet** (dep 36.2 ✓) så att riskklassningen (36.3) och dedupen (36.4)
kan försvaras — och regressioner upptäckas — med data ur körnings-API:t.
Måtten väljs i DORA-andan: hastighet och stabilitet lästa tillsammans,
aldrig hastighet ensam. Första körningen ger utgångsvärdet som resten av
T85-vågen jämförs mot — extra motiverat nu när dedupen är skarp och
main-push-runs redan ligger på ~50–56 s.

### Scope (task-36.5:s acceptanskriterier, kvitterade via kortet)

1. Fristående skript som rapporterar: ledtid för PR (median + p95), kötid
   från skapad körning till staging-jobbets start, röd-orsak per jobb,
   flaky-frekvens och dedupens träffkvot.
2. Körbart både manuellt och som steg i nattkörningen (`nightly.yml`).
3. Parallell testfil enligt husets mönster; testas mot fixtur-data, aldrig
   levande API i testet.
4. Testerna asserterar härledda mått ur känd fixtur-input — externt
   beteende, inte interna hjälpfunktioner.
5. Läsreglerna kodade i skriptet: fullständig SHA vid commit-uppslag
   (L314) samt rerun-medvetenhet vid avbrutna körningar (kan vara
   jobb-timeout, ej användaravbrott; L319).
6. Första mätningen körd och siffrorna citerade på kortet som utgångsvärde.

### Bärande invarianter (får ALDRIG regressa)

- **L322 — fail-closed-paraplyet:** `ci-passed` behåller `always()` +
  exit-1-steget; `gate-proof.yml` är vakten vid `ci.yml`-touch.
- **L326 — permissions-tak per reusable-anropare:** röres `nightly.yml`
  (nattsteget) måste varje anropares permissions-tak hållas; ett anropat
  workflow kan aldrig eskalera.
- **ADR-039/054 fetch-depth-invarianten:** exakt 3 bärande rader i
  `ci.yml` — orörda.
- **Merge-grinden (ADR-076):** ALL landning via branch + auto-merge-PR;
  direktpush till main är mekaniskt avvisad.
