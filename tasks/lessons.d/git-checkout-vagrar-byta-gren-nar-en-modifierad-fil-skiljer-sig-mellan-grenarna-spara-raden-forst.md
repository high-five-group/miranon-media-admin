# `git checkout <gren>` vägrar när en modifierad, spårad fil skiljer sig mellan grenarna — spara den tillagda raden, återställ, byt, återapplicera

**En ospårad ändring i en spårad fil (instrumenteringsloggen `docs/reference/review-instrumentering.jsonl`, appendad av `review-loop-beslut.mjs`) blockerar `git checkout` när filen har olika innehåll på från- och till-grenen; och ett `git checkout -b` som körs efter det misslyckade bytet i samma kommandokedja skapar grenen från FEL bas.** Mätt 2026-09-08 (S124 resume 1): huvudkatalogen stod på #2457:s gren (dev-server för Marcus ögonmätning), loop-beslutet hade appendat en rad, `git checkout main` avbröts — och `git checkout -b task-438-…` som följde utan `&&`-skydd skapade grenen ovanpå `e32ab273` i stället för `main`; upptäckt på `git log`, rättad genom att extrahera raden med `git diff -U0 | grep '^+{'`, `git checkout --` filen, byta gren, radera den felskapade grenen och appenda raden igen. Regel: bind grenbyten med `&&` så ett misslyckat byte stoppar kedjan; behandla loggraden som data att flytta (extrahera → återställ → återapplicera), inte som ett hinder att stasha bort.
